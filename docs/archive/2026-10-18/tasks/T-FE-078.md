## 背景

承接 [Q-078](../../../pending-problems.md#q-078) 的前端消费面缺口；用户已确认同时交付最小文件管理页面。

## 范围

按[文件页面设计](../../../design/frontend/file-management.md)新增文件 API 封装、页面、路由和权限常量，复用列表/表格/弹窗/HTTP 会话边界。与 T-ACCESS-116 对齐菜单和响应字段，不使用 mock 冒充真实接入。

## 当前口径

页面只承载已确认的文件操作，授权经既有授权页维护；不另建文件权限编辑器。后台按分类而非上传者校验，交互不暗示“仅我的文件”。后端字段与初始化已通过定向验证，页面与真实接口验收已完成。

## 验收对照

- [x] 页面与真实接口、菜单、权限接线。
- [x] 普通角色分类权限、失败响应与会话生命周期。
- [x] DTO 对账、前端门禁和真实页面验证。
- [x] 本地双轨核对、设计回写与 Q-078 联合收敛。

## 非目标 / 遗留

分享、编辑、网盘目录树、所有者 ACL、存储平台化不在范围。新的行为取舍、不可确认的依赖或权限边界必须详细说明后由用户决定。

## 验收结果

已完成实现、真实页面/接口验收、计划统一回归及本地双轨核对，详见[统一验收](evidence/standard-capability/verification.md)。
