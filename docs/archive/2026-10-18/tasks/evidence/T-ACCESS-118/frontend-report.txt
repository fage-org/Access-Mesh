### [P2] 成功返回的 JSON MIME 文件被误判为错误信封

**位置：** [frontend/src/api/file.ts:61](D:/codespace/Access-Mesh/frontend/src/api/file.ts:61)、[同文件:79](D:/codespace/Access-Mesh/frontend/src/api/file.ts:79)

**问题：** 下载封装仅凭 `blob.type.includes("json")` 就调用 `rejectEnvelope()`；该函数无论解包结果如何都会抛错，因此真实文件只要携带 JSON MIME，就无法下载。

**触发条件：** 获授权调用方上传分类为 `document` 的 `data.txt`，文件部分声明 `Content-Type: application/json`，内容例如 `{"ok":true}`；随后从新增文件页下载。

**影响：** 上传、列表和详情均可成功，服务端也正常返回文件，但页面始终提示下载失败，重试不能恢复。这是**本次新增下载适配器引入的兼容性缺陷**。

**证据：**

- `.txt` 属于现有扩展名白名单；上传服务对未知 MIME [只记录警告](D:/codespace/Access-Mesh/access-service/src/main/java/cn/ac/fage/accessmesh/access/platform/service/impl/FileAppServiceImpl.java:291)，随后原样保存 MIME。
- 下载服务[原样回显该 MIME 并返回文件字节](D:/codespace/Access-Mesh/access-service/src/main/java/cn/ac/fage/accessmesh/access/platform/service/impl/FileAppServiceImpl.java:543)，因此上述输入确实能走到误判分支。
- 审计导出采用相似判断，但其成功响应[固定为 CSV](D:/codespace/Access-Mesh/docs/design/access-service-api-contract.md:2187)，这一前提不能直接用于文件下载。
- 现有 [file.spec.ts](D:/codespace/Access-Mesh/frontend/src/api/file.spec.ts:8) 覆盖了 JSON 错误信封与普通文本文件，未覆盖携带 JSON MIME 的成功文件。

**建议：** 在下载适配层保留响应元数据，用明确的成功文件标识区分文件与错误，避免仅按 MIME 判错。可复用 HTTP 的 `beforeResponseCallback` 获取下载头，并确保服务端仅在成功读取文件后设置成功下载标识。补充上述成功文件与真实错误信封的双向用例，保持现有上传限制。
