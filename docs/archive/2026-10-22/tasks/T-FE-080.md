## 背景

现有子权限配置器只按类型过滤，管理员难以区分报表专属字段和允许引用的通用对象；本次保留原入口。

## 范围

在原授权页消费主资源限定的候选接口；补类型模式/来源声明、资源管理页必要的维护权限和只读关系展示；复用现有草稿、计划保存与错误处理。

## 当前口径

原子权限配置入口、维护来源和只读关系展示已接线。首次主子联合配置、切换报表候选隔离、部分通用实例授权及保存回读已由真实浏览器验证，Vitest、类型检查和 DTO 对账通过，见[实施验证](evidence/T-FE-080/verification.md)。

详细规则以[资源关系设计](../../../design/resource-association.md)及上列 design_refs 为准。

## 验收对照

- [x] 配置 A/B 时同名专属字段候选隔离；A/B 引用同一通用类型时均能选其全部有效实例，用户仍可获不同实例子集；未引用该类型则无候选；子项为零的合法上下文可首次配置。
- [x] 切换主授权/类型及迟到响应不会串用资源、勾选或草稿；加载失败、无权限、无关系分别可见，异常已有配置可诊断清理。
- [x] 专属实例及业务关系只读，通用实例沿原管理权限维护；类型声明新增或编辑受后端既定约束，不能通过前端默选改变模式。
- [x] 原主子联合编辑与保存行为保持；当前全选与 ALL 区分，条件/来源/维护方展示准确。
- [x] 新增 TS 响应字段与 tools/contracts/dto-fields.json 同步，既有 Vitest 与必要真实浏览器路径验证，页面设计与 DTO 覆盖说明回写。

验证层：按测试技能复用现有组件/hook/草稿案例；重点补 A/B 切换和响应乱序、共享候选、只读与失败路径，不重复业务引擎测试。

## 非目标 / 遗留

不建独立授权入口或 BI 页面，不实现全局搜索授权、模板、跨角色批量保存。
