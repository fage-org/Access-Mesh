## 背景

外评 P1（成立）。现状：`forceResetPwd=true` 登录后仅 6 秒 warning「请联系管理员重置」（login/index.vue:87-95），随后正常使用系统。定案链：T-ADMIN-022（2026-08-27）定非阻断提示的依据是「系统无用户自助改密通道（如需自助改密另行立项）」；该依据已被 T-PERM-067（2026-09-14）证伪——`/user/reset-password` 自身路径定位为全系统唯一自助改密通道（自身豁免权限校验）；T-PERM-066 同日定「自身改密成功置 forceResetPwd=false」。用户拍板（2026-09-19）：**自助改密页 + 阻断**。处置历程与修正依据见 decision-registry 2026-09-19 行。

## 范围

- 新页面 `src/views/change-password/`（路由 remaining.ts 注册，无需权限码——登录即达）。
- userKey 存储扩展（userId + forceResetPwd 阻断标记）与登录/登出/改密三处生命周期接线。
- 路由守卫阻断逻辑。
- 登录页 warning 分支删除、user.spec.ts 补登录响应 forceResetPwd 分支用例。

## 当前口径

- 阻断是导航层门禁（UX），不是安全边界——后端仍是最终授权边界；改密页自身经会话认证（登录态）可达。
- Gateway 可达性：`/api/access/user/reset-password` 需在 Gateway 会话入口族白名单内（T-GW-009 落地，用户拍板 2026-09-19）——否则快照判定对无 API:ACCESS 的普通用户 403，阻断落地即锁死目标人群；服务层门禁不变（Sa-Token 登录校验 + 自身路径豁免/非自身须 USER:RESET_PASSWORD）。
- 改密成功后不强制重新登录（会话保留）；如执行期发现后端改密使会话失效，按实际行为调整（改密后引导重新登录）。
- 首期 UI 不设旧密码字段：后端无旧密码校验（T-PERM-066「旧密码验证另立任务」），前端收集不校验的字段是假安全；文案用「设置新密码」。

## 非目标 / 遗留

- 旧密码校验（后端任务，另立）+ UI 加旧密码字段。
- 密码强度可视化策略升级（维持 8-32 长度契约口径）。
- 管理员重置他人密码流程（既有，不改动）。
- 改密成功跨标签即时通知（storage 事件广播）——共享存储 + 守卫重读已保证一致性，事件通知仅缩短延迟，不做。
- **端到端验收（acceptance 第 5 条，经 Gateway 真实用户全链路）**：✅ 已于 2026-09-20 计划归档批次执行通过（六项判据与完整记录见归档计划「当前进度」末行）——smoke-release-user（无 API:ACCESS 授权）真实管理链路造数 → 阻断 → 深链弹回 ×2 → 纯空白密码拦截（claude 外评 P3-1 配套用例）→ 改密成功放行 → force_reset_pwd 翻转 false + 新密码重登直达；「纯空白密码提交」用例已按建议纳入。
- **改密页无页内登出入口**（claude 外评存量，2026-09-20 维持现状）：userId 缺失态（升级部署时存量会话一次性窗口）提示「退出后重新登录」不可经页内执行——/login 对已登录用户被白名单弹回；multiple-tabs 为会话 cookie，关浏览器重开即强制重登自愈，不加页内登出入口。
