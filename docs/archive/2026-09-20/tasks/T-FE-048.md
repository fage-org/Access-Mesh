## 背景

外评 P1-04 + P3-14（同根因，均成立）。`refreshUserMenu()` 全仓仅 loginByUsername 与 initRouter 两处调用；权限授予页重试按钮（typePermDenied 降级态）读的仍是 store.permissions 旧值。场景：管理员给用户 A 新增 `USER:UPDATE` 后 A 的按钮不出现、撤权后按钮残留点击 403，只能 F5/重登。用户拍板（2026-09-19）：**403 触发自动刷新一次 + 手动入口**（弃轮询/推送——前者延迟=N 分钟且常驻请求量、后者需后端新事件机制属长期项）。

关键约束（外评修法盲点）：管理员授权发生在管理员自己的浏览器，页面内刷新帮不了被授权人——机制必须落在被授权人会话侧，403 触发正是「被授权人下一个动作即自愈」的形态。

## 范围

- 提炼统一「会话能力刷新入口」（单函数：权限串+侧栏+门禁 path 集/状态机原子更新），四个调用方共用：initRouter、403 自动刷新、手动入口、授予页重试——仅刷 store 不重建侧栏则「下一个动作自愈」只完成一半。处置历程见 decision-registry 2026-09-19 行。
- `src/utils/http/index.ts` 响应拦截器 403 分支（现仅注释「由页面层自行处理」）加自动刷新触发（去重窗口 + 不重放请求）。
- 顶栏「刷新权限」入口（lay-navbar 工具区）。
- `src/views/perm/grant/utils/hook.ts` `retryLoadDeps` 先走能力刷新入口。
- 回归锁：http 拦截器 spec + grant hook.spec 补用例。

## 实现落点（2026-09-20）

- `src/router/utils.ts`：`refreshSessionCapability()` 统一入口（`export`，getToken 守卫 + refreshUserMenu + `rebuildSidebarFromUserMenus`）；initRouter 拉取分支改走该入口（外部形态不变）。
- `src/utils/http/index.ts`：模块级 `triggerCapabilityRefreshOn403`（10s 窗口起算于触发时刻 + 在途双保险；排除 user-menu 自身）+ 拦截器 403 分支调用；`CAPABILITY_REFRESH_403_WINDOW_MS` 导出供测试消费。
- `src/layout/hooks/useNav.ts` + `lay-navbar/index.vue`：`refreshPermission`（模块级在途 ref 防并发双发；成功「权限已刷新」/失败错误 message——2026-09-20 用户拍板）+ 工具区图标按钮（在途旋转）。
- `src/views/perm/grant/utils/hook.ts`：`retryLoadDeps` 先 `refreshSessionCapability()`（失败 catch 不阻断）再 `loadDeps()`；`retryInFlight` 在途标记（函数短路 + 重试按钮 loading 双保险——评审 P3-3 处置，2026-09-20 拍板补 loading）。
- 回归锁：`src/utils/http/index.spec.ts`（锁①② + 窗口过期/user-menu 排除/失败静默/401 不扰等附加锁，含全撤销落占位边界）；`hook.spec.ts` 锁③ + 刷新失败不阻断重试边界 + 重试在途防重入锁。红跑实证（stash 源码改动对旧实现）：新增行为用例 8 红/9 绿——三把验收锁全红，既有用例与两条特征锁（user-menu 排除、401 不扰对旧实现恒真）不误伤。
- 文档回写：login.md 新增「会话权限热刷新」节 + user-menu 拉取时机四通道 + 403 分支口径；permission-grant.md §10 重试语义句更新。

## 当前口径

- 403 ≠ 必然权限变更（可能是配错/越权访问）——刷新无害（多一次 user-menu 请求），按钮显隐以最新事实为准。
- 403 去重窗口 **10s**（2026-09-20 用户拍板；起算于触发时刻）；手动入口不受窗口限制（显式动作立即响应）。
- 手动入口失败弹错误 message（2026-09-20 用户拍板：显式动作配显式反馈）；403 自动刷新失败静默仅 console.warn——两通道口径刻意区分。
- 刷新后 menus 变化不清理 multiTags 已缓存标签（标签指向的路由由后端 403 兜底）；此边界登记任务内注记。
- user-menu 自身 403 不触发刷新（刷新入口即该请求，其 403 下重发无自愈可能）。

## 非目标 / 遗留

- 服务端推送（版本号/SSE/WebSocket）——长期项。
- 403 自动重放原请求——不做（循环风险，用户重新点击即可）。
- 403 去重窗口跨登出/登录残留（2026-09-20 拍板接受现状，双轨评审代码轨 P3-1）：同浏览器快速换人登录时新会话首个 403 的自愈最多延迟 10s（手动入口不受窗口限制）——清窗需 http 模块反向挂登出钩子（新增耦合边），收益不成比例。
- refreshUserMenu 无代际守卫的跨会话旧响应竞态（2026-09-20 拍板登记不修，双轨评审代码轨 P3-2，Q-016 同族）：403/手动刷新通道为新增触发面（initRouter F5 与登录并发的同款窗口本任务前已存在）；触发窗极窄（亚秒返回且恰晚于新登录全链完成）、后果可自愈（下一次 403/手动刷新修正）；T-FE-054/056 触达会话面时与 Q-016 一并收口。
- 手动入口无会话竞态下的「权限已刷新」提示失真（2026-09-20 拍板接受现状，双轨评审代码轨 P3-4）：401 logOut 清 token 与点击赛跑的近零触发面，toast 随跳登录页即遮蔽。
- 同会话跨通道并发刷新竞态（2026-09-20 codex 外评 P2-1 拍板登记不修，claude 未报、主代理亲核成立）：三个在途守卫（http `capabilityRefreshInFlight`/useNav `capabilityRefreshing`/hook `retryInFlight`）彼此独立，`refreshSessionCapability` 自身无 single-flight——403 自动刷新在途时点手动/重试，旧响应晚到可覆盖新权限串并重建侧栏（「手动提示成功却显示旧数据」）；触发=点击落在网络在途窗口内+权限恰在两次请求间变化；无越权（后端 403 兜底）。Q-016 同族（「旧响应覆盖新状态」竞态家族，跨会话+同会话两变体）；修法方向=入口内共享在途 Promise single-flight，T-FE-054/056 触达会话面时一并收口。
- 手动入口 mix/horizontal 布局缺口（2026-09-20 codex 外评 P2-2 与 claude P3 同报，拍板登记不修）：按钮仅挂 vertical 工具区，mix/horizontal 顶栏由 `NavMix.vue`/`NavHorizontal.vue` 手写复制体渲染、无此入口（三份复制体系本次漏挂的根源）；该两布局靠 403 自动通道（与布局无关）+F5 兜底；**修法定向=抽公共小组件三处工具区共用（用户拍板，非补挂两处复制），暂不实施**；边界注记已同步 login.md「会话权限热刷新」节。
