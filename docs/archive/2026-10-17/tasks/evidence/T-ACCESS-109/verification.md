# T-ACCESS-109 验收记录

日期：2026-10-17。范围以[认证设计](../../../../../design/browser-session-authentication.md)为准。

## 已交付边界

- 租户与平台分别使用固定名 HttpOnly Cookie；网页登录响应只有会话/用户元数据，原 Bearer 登录与 OAuth2、服务凭证保留。
- Origin/Referer、显式请求头、token-session 中的随机会话/CSRF 标记共同校核；同域 Cookie 与 Bearer 冲突拒绝，不回退。
- 注销请求只对应原会话；响应不写 Set-Cookie；前端立即清旧 UI 和元数据，失败明确提示，不保存补注销队列或独立注销凭据。
- V1 升级重新登录；登录元数据一次完整写入，新账号不继承旧账号的展示/权限/强制改密标记；未加载 SSO 示例按用户确认删除，记住我分支保留。

## 浏览器验证边界

使用最终前端构建、独立回环主机 127.0.0.2 上的临时模拟 API，以及合成 alpha/beta/operator 会话；不读取或使用真实账号、密码、验证码，不改真实部署。测试夹具只建立元数据和 HttpOnly Cookie，真实账号密码/验证码/门禁/数据库链由 PG 与 E2E 测试覆盖，不能把模拟后端当作真实服务端鉴权证明。

已观察：浏览器发送认证 Cookie，但 document.cookie 仅见非认证标签标记；localStorage 不含原生认证令牌；业务请求携会话标记且没有 Authorization。模拟注销失败后出现“服务器尚未确认退出”，立即回登录页；刷新仍为登录页，残留 Cookie 不恢复身份。其他标签显示阻断提示，重新载入采用新账号。失败退出后换账号没有后台补注销请求。平台与租户页面可同时使用各自会话。最后构建再次验证退出、刷新与换账号行为。临时标签、模拟服务和构建目录中的测试夹具在验收后清理。

## 验收前修正与证据强度

- 共用策略先以未实现状态验证拒绝与绑定断言失败，再实现；简化方案补“固定 Cookie 名称”和“标记单独不能注销”断言，旧候选方案失败后完成替换。
- 真实 PG 用例最初发现已校核的 Cookie 尚未进入 Sa-Token 较早捕获的请求上下文，userinfo 返回 401。改用公开 setTokenValueToStorage 请求内存桥接后，定向 2 项及最终全量均通过；不通过恢复通用 Cookie 读取规避问题。
- 首次完整回归暴露 90002 错误码快照和索引遗漏，修正后 8 项隔离测试通过，再执行上述最终完整回归。
- 类型检查发现格式化使 @ts-expect-error 脱离实际报错属性；移到 method 属性前，保留 POST-only 反向编译保护，最终类型检查通过。
