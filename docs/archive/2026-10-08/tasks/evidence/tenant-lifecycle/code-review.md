## 实证通过项

- 独立平台认证域与租户原生、OAuth2、服务凭证分离；相同数字账号 ID 不构成身份替代，平台 token 不能进入客户业务入口。
- 平台账号写入按统一管理锁串行，等待后重新读取操作者；最后管理员保护只数启用状态。并发互停、审计失败回滚、密码代次与一次展示已由真实 PG/会话测试覆盖。
- 租户开通在同事务完成注册、参数化标准种子、固定图及成功审计；重复编码拒绝，失败不保留业务图。没有复制其他租户的实时数据。
- 首管理员凭据恢复保留客户决定的停用和角色状态，已删除明确拒绝，并解除临时登录失败锁定。成功审计与写入同事务，失败尝试独立审计，不记录密码与完整请求体。
- 门禁在数据库行锁下预阻断、提交后凭本次令牌发布；延迟恢复不能覆盖后来停用，回滚后维持保守阻断再按数据库修复。Redis 实际进程、主节点身份、格式、会话代次均检查，没有正向 L1 放行缓存。
- Gateway 在热权限快照前校验租户状态，服务端覆盖原生、OAuth2、M2M，新任务在进入任务体前检查。跨服务验收证明恢复后旧用户令牌不复活，有效服务凭证恢复。
- 两类浏览器身份使用独立键与请求分支；平台 401 不清租户状态。明文初始密码不持久化，弹窗关闭即清理；自身重置平台密码时不先刷新列表而丢失交付内容。

## 存疑待用户决策项

已确认并落地：最后管理员保护只计启用状态，不计临时登录锁定；Redis 重启后所有租户原生会话重新登录。没有剩余待决项。

## 机制必要性

独立认证域、平台审计、租户注册和 Redis 协调均对应明确产品约束；状态修复、发布令牌和进程标记分别覆盖故障、迟到发布和旧快照恢复。失败审计复用既有切面，密码强度／生成与验证码复用公共实现；没有新增业务缓存体系、消息队列、线上迁移框架或客户代操作入口。本次未发现需另行拍板的可裁剪机制。
