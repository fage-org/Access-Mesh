# T-FE-024 ReConditionPicker + ReConditionEditor + ChildPermissionInline

> 状态：done
> 复杂度：🟡 中
> 来源：T-FE-001 组件池汇总确认派生（2026-07-12）

## 背景

T-FE-001 跨页组件抽象池汇总确认：权限条件选择器 + 规则编辑器在 T-FE-009（条件管理页独立 CRUD）和 T-FE-014（权限授予页附加设置弹窗内联新建）两处使用，模式一致（搜索/摘要/启用状态/内联新建/规则序列化校验），确认抽取为共享组件。

T-FE-014 §15.4 明确：「条件编辑/选择器已达第二个使用场景，确认后续抽取 ReConditionPicker/ReConditionEditor」。

## 设计变更影响（2026-07-12）

`permission-grant.md` §16（第二轮修订）将右栏改为授权弹窗 + 本次变更记录，附加设置和子权限需内联到授权弹窗步骤四。审核已确认：T-FE-024 先完成组件抽取（含 ChildPermissionDrawer 内联化），T-FE-026 授权弹窗再基于新组件；`AdditionalSettingDialog` 组件抽取 + `ChildPermissionDrawer` 内联化归本任务，授权弹窗编排归 T-FE-026。依赖已记录在 T-FE-026，结论已回写 §16.8 R9。

## 组件设计

### ReConditionPicker

- 按名称/编码搜索条件
- 展示规则摘要 + Gateway 可评估状态（gatewayEvaluable，T-PERM-017）
- 只列启用条件；已绑定后停用的条件可回显但保存前需替换或清除
- CONDITION:CREATE 权限时显示「新建条件」入口，创建成功后自动选中并回到当前弹窗
- 无创建权限时不展示不可用入口

### ReConditionEditor

- 从 ConditionForm 抽取结构化编辑器
- logic AND/OR + items[] 4 类型（DATE_RANGE/TIME_RANGE/IP_WHITELIST/IP_BLACKLIST）
- params 动态表单（date/time-picker + cidrs tag 输入）
- 规则序列化 + 校验逻辑共享（两处必须使用同一规则模型）
- 接收 gatewayEvaluable 校验上下文（开关属父表单）+ 白名单预校验（T-PERM-017）

### ChildPermissionInline

- 从 T-FE-014 `ChildPermissionDrawer` 抽取为内联组件
- 展示子权限树 + 授权状态
- 支持授予/移除子权限
- 内联在授权弹窗步骤四，不再以 Drawer 形态打开

## 实现记录（2026-07-12）

已完成组件抽取与三处回写，`pnpm build && pnpm typecheck && pnpm lint` 全过。

### 新建共享组件

- `components/ReConditionEditor/`：v-model（ConditionRules）+ expose validate()；`gatewayEvaluable` 作为校验上下文 prop 传入（开关属父表单，规则属 Editor）。
- `components/ReConditionPicker/`：自包含精简 create-only 元信息表单 + ReConditionEditor + createCondition API；`conditions` 必传（纯受控）；expose validate()（停用条件保存前阻断）；候选项只显示启用项 + 当前选中的停用项；选项展示 gatewayEvaluable 状态；创建顺序 emit created -> emit update:modelValue -> 切回选择态。
- `components/RePermissionCell/`：PermissionCell 机械上移，供 PermissionMatrixPanel + ChildPermissionInline 共用。
- `components/ChildPermissionInline/`：从 ChildPermissionDrawer 内联化；不 inject store，通过窄接口 binding（getCell + toggleCell）隔离草稿；onOpenSetting emit payload（不含 childKey），由使用方 adapter 算 key。

### 共享类型整理

- `utils/condition-rules.ts`：规则模型（ConditionRules / 序列化 / 摘要 / 常量）从 permission-condition/utils/types.ts 抽出，消除 `api/permission-grant.ts` 反向 import 页面工具的分层倒置。
- `permission-condition/utils/types.ts`：re-export 规则模型 + 保留 ConditionFormData。
- `permission-grant/utils/child-binding.ts`：pgStore adapter（createChildBinding），实现 binding 契约 + 额外 getCellKey/getParentKey 供 index.vue 算 key。

### 回写使用点

- `ConditionForm.vue`：条件规则区 -> ReConditionEditor，validate 委托。
- `AdditionalSettingDialog.vue`：条件选择 + 内联新建 -> ReConditionPicker，删除内联 ConditionForm 依赖。
- `PermissionMatrixPanel.vue`：PermissionCell -> RePermissionCell。
- `index.vue`：ChildPermissionDrawer -> el-drawer 包裹 ChildPermissionInline + childBinding adapter；onOpenChildSetting 算 childKey/parentKey 构造 AdditionalSettingContext。
- 删除旧 `ChildPermissionDrawer.vue` + `PermissionCell.vue`。

### 决策落地

| 决策 | 落地 |
|---|---|
| 1 ReConditionPicker 自包含 | 精简 create-only 表单 + ReConditionEditor，不反向引用 ConditionForm |
