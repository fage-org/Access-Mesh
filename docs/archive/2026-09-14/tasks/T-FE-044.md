# T-FE-044 Phase 3 补遗联调：资源依赖（3.4）

## 背景

前端 Phase 3 联调批次（T-FE-015~022 + T-FE-037 九任务）未覆盖 3.4 资源依赖页——该页仍为 Phase 1 mock 驱动形态。2026-09-14 轻量清扫批次核实登记 Q-011/Q-012（pending-problems），用户拍板转本任务收口。

前置事实（2026-09-14 调研核实）：

- **api 层已就位**：`frontend/src/api/resource-dependency.ts` 按 T-PERM-031 契约收口形态对齐（业务键 create/update、字符串线格式操作位、R 信封解包）；页面 hook 仅消费真实 api 层，无 mock 直接依赖。
- **Gateway 断点**：`BootstrapGraphDefinition.apiRoutes()` 未注册 resource-dependency 六端点（页面引用数据端点 resource-entity/tree、operation-permission/list 已在册）——未注册路径 fail-closed 403，这是删 mock 后真实链路的实质断点。
- **业务门禁已在图**：DEPENDENCY VIEW/CREATE/UPDATE/DELETE/SYNC 五档 scopeAll 已由 T-PERM-031 预置（businessGrants），零新增。
- **mock 拦截链**：`mock/resource-dependency.ts` 六端点 url 与真实路径逐字一致、无条件注册，dev 下全量拦截；其 `_shared/resource-fixtures` 依赖自 T-FE-018 后唯一存活引用方即本 mock（沿革链见 fixtures 头注）。
- **Q-012 死文件**：`mock/refreshToken.ts` 拦截虚构端点 POST /refresh-token（模板 `{success,data}` 壳、非 R 信封），src/ 零调用；前端无 refresh-token 体系（T-FE-041 定案：会话到期清本地会话回登录页，Gateway 401 兜底）。
