# T-GW-006 集成测试基线

> 来源：[gateway-fail-mode-plan](../gateway-fail-mode-plan.md) 任务 C-6

## 依赖说明

- **T-GW-002**：fail-closed 实现已落地，集成测试需验证其行为。

## 重新界定决策

**2026-06-28 决策**：不在 Access-Mesh 项目内编写集成测试，理由如下：

1. **Gateway 集成测试需要完整基础设施**：Nacos（服务发现）+ Redis（订阅失效）+ Sa-Token，在 `@SpringBootTest` 中 mock 这些依赖复杂度高、维护成本大。
2. **测试服务应独立演进**：专门的测试服务可以独立部署、独立迭代，不受 Access-Mesh 主项目发布周期约束，适合运维/qa 团队维护。
3. **单元测试已覆盖核心逻辑**：`PermissionFilterFailModeTest`（8 个 fail-mode 测试）+ `PermissionFilterMetricsTest`（11 个指标测试）+ `PermissionFilterTest`（5 个组合路径测试）共 24 个单元测试已覆盖三模行为、显式失效、指标递增等核心场景。

### 后续方案

- 在独立仓库创建专门的 Gateway 测试服务，可部署到测试环境
- 测试服务能力（后续按需实现）：
  - HTTP 场景验证：杀 perm-center 后 Gateway 返回 503（fail-closed）/ 放行（fail-open）/ 续命（stale-allow）
  - Prometheus 指标校验：查询 `/actuator/prometheus` 验证 Counter 递增
  - Redis 广播失效验证：发送 `perm:invalidate` 事件验证 Gateway 清缓存行为
