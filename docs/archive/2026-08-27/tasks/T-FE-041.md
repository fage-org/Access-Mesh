# T-FE-041 前端真实登录链路与默认导航收敛

## 背景

前端登录仍为 mock 链路，且真实差异远不止信封：后端 `LoginReq` 必填 `tenantId/username/password/clientId` 并在运行时强制校验 `captchaId/captchaCode`（`/auth/captcha` 端点存在、`admin-web` 客户端种子已存在），而登录页硬编码 `admin/admin123` 只提交用户名密码；store 以 `res.success` 判定（后端 PermResult 无该字段，成功也不存令牌）；`setToken` 需要绝对时间 `expires` 而后端返回 `expiresIn`（秒）；普通 Sa-Token 会话无 refreshToken，前端不应调用不存在的 `/refresh-token`。路径层面：Gateway 仅路由 `/admin/**`、`/perm/**`（StripPrefix=1），而 `permission-grant.ts` 直连 `/api/perm/**`、`user-manage.ts` 直连 `/user/**`——不切换路径则经 Gateway 全部 404。frontend/mock/ 21 个文件约 16 个 api 模块标注 Phase 1 mock。本任务在 bootstrap（T-ACCESS-020）之后实施；默认导航收敛范围自 T-FE-042 并入。

## 范围

- 登录端点/信封/代理/菜单接线四项对齐 + mock 开关核实。
- 登录相关页面（登录页、主页框架）适配真实响应。
- 默认导航收敛（隐藏高级模型入口，保留代码）。

## 当前口径

- 统一信封是全站口径；Gateway 对外 HTTP 状态码差异化（401/403/503）按 project-rules §3.3 处理。
- 仅登录 + 主页 + 一个授权场景，管理页不动。
- 导航收敛只隐藏不删除，隐藏入口的页面与路由保留（按需开关恢复）。

## 非目标 / 遗留

- 不删除各管理页 mock（Phase 3 联调任务逐页切换）。
- 不做全站 BigInt 类型改造（T-PERM-028 归口）。
- 不删除被隐藏页面的业务代码。

## 实施记录（2026-08-24 done）

### 设计定案（三项）

1. **动态路由**：纯静态路由模式——`initRouter` 不再请求 `/get-async-routes`（真实后端无此端点且模板无 catch 会卡死登录、演示菜单与导航收敛口径冲突），`handleAsyncRoutes([])` 直接装配；`src/api/routes.ts` 删除，`mock/asyncRoutes.ts` 保留文件不再被消费（恢复指引见其头部注释）。
2. **mock 解耦**：`VITE_MOCK_LOGIN` 开关（.env.development 默认 false）——false 时 mock/login.ts 注册空路由数组（真实 `/auth` 链路全程经 vite proxy → Gateway；fake-server 中间件先于 vite proxy 执行，同路径 mock 必须不注册）；true 时响应壳已对齐 PermResult（`/auth/login` 返回 LoginResp 形态），前端代码零分支。
3. **刷新链路删除范围**：全链路删除——http 拦截器自动刷新（isRefreshing/请求队列/重试）、`store.handRefreshToken`、`api/user.ts`（`refreshTokenApi`/`UserResult` 旧壳类型，`getLogin` 移入 `api/auth.ts` 按真实契约重写）；`mock/refreshToken.ts` 文件保留不动。

### 改动清单

- **登录链路**：`api/auth.ts` 重写（`getCaptcha`/`login`/`LoginFormData`/固定常量 `FIXED_TENANT_ID="1"`+`FIXED_CLIENT_ID="admin-web"`，保留 `getUserMenu`）；`store/user.ts` `loginByUsername` 改 unwrap 异常路径 + `expiresIn` 转绝对时间 + `refreshToken ?? ""`；登录页删除 admin/admin123 硬编码、新增验证码输入框+图片（点击刷新）+ 失败无条件刷新；`rule.ts` 增 captchaCode required。
- **401 窄处理与过期语义**：响应拦截器仅 HTTP 401 → `logOut()`；请求拦截器本地过期 → `logOut()`（无令牌放行由 Gateway 401 兜底）；白名单改 `/auth/captcha`+`/auth/login`。
- **路径切换**：五模块（role-manage/type-def/resource-operation/permission-condition/permission-grant）76 处 URL `/api/perm/**` → `/perm/api/perm/**`（Gateway 外部路径，StripPrefix=1）；对应 mock 旧路径自然失配（保留不删）；`grant-store.spec.ts` 3 处断言同步。
- **vite 代理**：`/auth`、`/admin`、`/perm`、`/example` 四条同路径转发（`VITE_PROXY_TARGET`，默认 `http://localhost:8080`，无 rewrite）。
- **导航收敛**：`system.ts` 顶级 + 13 子页 `showLink: false`（Phase 3 开放清单 4 页：组织与用户/角色管理/服务与接口/权限查询；长期隐藏 9 页）；`error.ts` 模板演示菜单同口径隐藏（路由保留）；`perm.ts` 原本 showLink:false 不变。
- **模板演示代码清理**：`views/permission/`（page/button 动态路由演示页，依赖已删除的 mock 动态路由注入且引用旧登录签名）删除。
- **生产 mock**：`VITE_ENABLE_PROD_MOCK=false` 既有机制核实——生产构建产物 index.html 无 fake-server 客户端脚本注入。

### 验收证据（2026-08-24，T-ACCESS-020 bootstrap 环境）

- **构建**：`pnpm typecheck` 通过；`pnpm test` 206/206 全绿；`pnpm build` 成功且产物无 mock 注入。
- **真实链路（compose 基础设施 + access-service bootstrap + Gateway 8080 + 前端 dev）**：
  - curl 经 Gateway：`POST /auth/captcha` 200（base64 图片）；错误验证码登录 HTTP 200 + code=10901"验证码错误"；正确验证码（Redis 读码）登录 200，`LoginResp` 字段与前端类型逐一匹配（refreshToken=null/expiresIn=7200）；`POST /auth/user-menu` 带 token 返回 roles=["Bootstrap Admin"]+4 条权限串；无 token 访问 `/perm/api/perm/role-resource-permission/list` → **HTTP 401**（前端窄处理触发条件）。

| # | 级别 | 问题（核实结论） | 处理 |
|---|---|---|---|
| 1 | 中 | 登录失败后 `refreshCaptcha()` 未纳入 loading（catch 不返回 promise，finally 立即恢复按钮），旧 captchaId/输入在新码到达前仍有效——慢网下可立即重提交已消费旧码 | `refreshCaptcha` 发起即清 captchaId+captchaCode（旧码即刻失效）；catch 返回刷新 promise，loading 覆盖刷新全程 |
| 2 | 中 | `sub-perm-allowed-types` 切真实路径后必然 404（后端 Controller 无此端点，api-contract §6.5.2 已定稿未实现）| 属既有后端欠账（mock 时代被掩盖）：登记遗留（见上）+ `permission-grant.ts` 注释标注"后端未实现、子权限区暂不可用、不阻断主权限场景"；不在前端任务内补后端 |
| 3 | 低 | 固定 `tenantId/clientId` 放 `...data` 之前，结构化类型下可被多余字段覆盖 | 展开顺序调整为 `{...data, tenantId: FIXED_TENANT_ID, clientId: FIXED_CLIENT_ID}`，常量最终覆盖权 |
| 4 | 低 | 新增单测 menus 空夹具且未断言 `user.menus`/localStorage 持久化；401 用例绕过拦截器未覆盖清会话副作用 | 夹具 menus 改非空并断言 `user.menus` 与 `storageLocal.setItem(userKey, ...)`（共享 mock 实例）；拦截器副作用经 spec 头部注释明确边界（不为 10 行拦截器搭 axios 基建，真实 E2E 已覆盖——避免过度设计） |
| 5 | 低 | login.md 表述不一致：user-menu "失败仅 console.warn"与 401 rethrow 实现矛盾；`admin-service-api-contract.md` 实际无登录端点契约却被引作权威 | login.md 两处更正（401 不降级语义；契约来源改为后端 Controller/DTO 并注明文档缺口已登记） |
