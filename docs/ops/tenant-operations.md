# 租户与平台运营

依据：[租户生命周期](../design/tenant-lifecycle.md)、[API 契约 §26](../design/access-service-api-contract.md#contract-section-26)。

## 首次部署与开通

首次部署使用权威 DDL 建空库。配置 `ACCESS_PLATFORM_BOOTSTRAP_ENABLED=true`、`ACCESS_PLATFORM_ADMIN_USERNAME`（默认 admin）与 `ACCESS_PLATFORM_ADMIN_PASSWORD`（8–32 位，含字母和数字）。平台账号仅在空账号表时初始化；后续修改环境变量或重启不会覆盖已存在账号的密码。环境变量和密钥文件不提交仓库。

首次启动不创建任何租户或 OAuth2 客户端。访问平台登录页（默认 hash 路由为 `/#/platform/login`）登录运营界面，再从租户页开通。第一个租户与后续租户均自由填写不可变编码（小写字母开头，最长 64，允许数字、连字符）。客户使用 `/login`，填写该编码及交付的首管理员凭据；首次改密后重新登录。客户 OAuth2 接入由其管理员另行注册客户端。

开通成功返回的随机密码只展示一次。网络中断或超时不能证明未提交：先按编码查询是否已存在，已存在时使用首管理员密码重置重新交付。平台始终可重置最初的首管理员凭据，但不会恢复其状态或角色；原账号删除则明确拒绝，不能重新造一个恢复账号替代客户决定。

## 停用、恢复与门禁未就绪

停用成功后，新请求和新启动任务被拒绝；已进入执行的工作不强制中断。恢复后用户重新登录，旧 OAuth2 链继续失效；仍有效的服务凭证恢复可用。

运营界面分别显示数据库登记状态与访问状态。`UNAVAILABLE` 表示门禁未知或与数据库不一致，当前拒绝租户请求。正常请求只读共享 Redis，不逐次回源数据库。access-service 每次巡检最多扫描 200 个租户，批量识别并在持行锁时重建；默认巡检间隔 1000ms。需要诊断时检查 Redis 连接、执行 Lua/INFO 权限及服务日志；禁止手工写入 ENABLED 门禁值。

返回 503 时可能已提交数据库变更及审计，但尚未完成门禁发布。先刷新详情核对；不要把“启用已登记”的审计等同于“访问已恢复”。Redis 故障时平台租户列表仍可显示数据库事实与未就绪访问状态；需要 Redis 的登录和写入操作仍可能不可用。

## Redis 与备份恢复

首期只支持单主 Redis，门禁协议在脚本中验证当前进程及主节点身份；不支持以 Sentinel/Cluster 自动故障切换保证立即停用。日常 Redis 重启后，持久化中的旧进程门禁值被视为未知，自动重建期间拒绝访问；所有租户原生会话必须重新登录，不能依靠恢复 Redis 快照继续使用旧 token。OAuth2 和平台账号分别继续按数据库密码指纹／租户代次和平台凭据代次校验。

切换实例或恢复备份必须先阻断入口和任务启动，并停掉旧实例，防止双写。核对实际 PostgreSQL 数据事实后启动 access-service 重建门禁，确认全部登记租户的访问状态与数据库一致，再开放流量。不得在仍承接请求的 Redis 上热覆盖旧备份。

若恢复了 PostgreSQL 旧备份，租户代次和密码事实可能同时回退，不能只重建门禁就认为旧令牌永不复活：开放流量前清空该部署专用 Redis 逻辑库中的旧会话、授权码和刷新记录，并轮换 JWT 签名密钥后重启签发与验签服务。共享 Redis 逻辑库必须先分离本部署的状态，不能对其他系统执行清库。有效服务凭据的数据库记录按恢复后的事实处理。外部离线验签系统的撤销生效范围仍遵循接入方约定。

## 平台账号离线恢复

仍有平台管理员可登录时，使用平台账号页受审计的重置入口。所有平台管理员失联时，由部署者在维护窗口离线恢复：

1. 停止外部流量并确认目标部署与目标平台账号，备份当前事实。
2. 在受控环境生成随机密码和 BCrypt 哈希。只向数据库写入哈希，不把明文放入命令历史或日志。
3. 在同一数据库事务内，锁定目标 `platform_account` 行，更新其密码哈希、`force_reset_pwd=true`、`status=1`、`credential_version=credential_version+1` 及更新时间；写入 `platform_audit_log`，动作 `PLATFORM_ACCOUNT_OFFLINE_RECOVERY`，`operator_id=NULL`，以说明字段记录部署方工单，不伪造租户用户。审计失败则回滚。
4. 清除该账号 `platform:login:fail:<username>` 临时失败计数；恢复入口，仅向接收人一次交付随机密码。接收人首次登录必须更换密码并重新登录。

直接修改初始化环境变量不构成恢复流程。平台账号不删除，租户也只停用／恢复，编码不复用。存量开发库继续沿用仓库重建政策；本次不提供在线迁移程序，任何实际重建必须由部署方核实数据保全后执行。
