## 背景

P2×4 批（外部持续审查发现，2026-10-12/14 主代理核实成立）：

- **类型候选截断**（探针实证）：`resource-operation/utils/hook.ts` mounted 单次 `getTypeDefList` 取 `res.items` 不读 hasNext（API 首批硬上限 200）；接口映射、授权页、冲突规则同模式。第 201 个类型无法进入建资源/准入/授权操作。`api/type-def.ts` 旧注释「字典全量（上限 200）」掩盖首批语义。
- **新增用户无组织**（探针实证）：MemberTab 打开弹窗置 `orgId=null` 提交，表单无组织必填规则；创建成功后用户无 sys_user_org 关系，目录/详情/候选按默认树裁剪均不可见，界面流程中断（API 返回 id 未被承接）。
- **自动授权边界提示位置**：PREVIEW_BOUNDARY_NOTES 全仓唯一渲染点在 GrantPreviewDrawer 成功分支内；直接保存路径的管理员事前看不到「目标权限独立可用」「全量/继承不作种子」两条关键含义。
- **外链菜单判定**：`SidebarLinkItem` 以 `isUrl(to.name)` 判外链并从 name 取 href，而现役 buildSidebarMenus 故意不产出 name（避免本地路由 name 冲突）——EXTERNAL 菜单落入 RouterLink 分支导航到 `/https://...` 错误路径（探针实证）。

## 范围

五个前端可用性/正确性缺陷；后端契约不动（API orgId 可选、目录裁剪、类型分页上限 200 均为现行正确边界）。

## 当前口径

续页复用一个明确的完整加载或远程分页选择入口（量大用 useRemotePagedOptions 同款）；不调高单页上限。外链适配以原生节点 path 为来源，保留必要 name=URL 模板兼容，不给本地菜单重加后端 name。边界提示复用既有文案不新增确认向导。

## 验收对照

见 frontmatter `acceptance`；类型截断与外链判定用例须旧实现下失败。

## 非目标 / 遗留

不开放全租户用户列表、不做孤立用户治理；iframe 站内嵌入语义另行核对（见待解决问题清单 Q-072 关联范围）。
