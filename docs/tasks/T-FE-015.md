# T-FE-015 Phase 3 联调：组织与用户 + menus 接线

> 状态：in-progress（2026-08-31 启动；任务卡为启动时补建——menus 接线属跨页基础设施且承载三项设计定案，详细范围入卡，见 phase3-plan 2026-08-31 进度日志）

## 背景

Phase 3 首个联调任务。前置事实（调研核实）：

- 登录链路已是真实接口（T-FE-041，`VITE_MOCK_LOGIN=false`），登录时拉 `/auth/user-menu` 存 user store（menus 内存态，F5 丢失）
- 组织与用户页 api 层（`frontend/src/api/user-manage.ts`）21 个端点全部裸路径，仅被 dev mock（`vite-plugin-fake-server`，`frontend/mock/user-manage.ts`）拦截；后端实态对照：18 个存在、2 个已删除（`/user-role/assign|revoke`）、若干字段级差异（见 acceptance 第 1 条）
- 侧栏读 permission store wholeMenus（静态路由树，T-FE-041 后仅「首页」可见）；`filterNoPermissionTree` 只认 `meta.roles` 不消费 `meta.auths`（本项目页面只有 auths）——T-PERM-037 收口定案：不改 filterNoPermissionTree，接线归本任务
- **sys_menu 空表**：bootstrap（T-ACCESS-020）未种菜单行，空库 `/auth/user-menu` menus 恒为空树；菜单管理页尚未开发无其他造数入口
- **固定图无 ORG/USER 页面门禁**：仅 `USER:CREATE`/`ROLE:CREATE`/`ROLE:MANAGE`；首管理员进组织与用户页全 403，且 checkCanGrant「先持有才能转授」→ 空库无授予起点（DOMAIN:VIEW/SERVICE×4/CONFLICT_RULE×4/DEPENDENCY×5 死锁防护同款）
- permissions 按钮串格式 `资源类型:操作码` 前后端同源（`PermissionViewAppServiceImpl` L1248），`hasPerms` 直接可用

## 设计定案（2026-08-31）

1. **菜单种子来源 = bootstrap 幂等种子**（扩展 T-ACCESS-020 固定图；重建库自动恢复；菜单管理页开发前的唯一造数入口）
2. **种子范围 = 一次种全部 14 页**（13 个系统子页 + welcome 首页；权限授予页不进菜单——其隐藏属交互入口设计（角色管理页按钮进入）非导航收敛）。9 个「长期隐藏」页随本定案放开菜单可见性（可见性由 v3.5 派生控制，admin 全可见；普通用户无授权不可见）
3. **固定图补授 = 全档 17 条**（页面门禁 18 档中 USER:CREATE 已在图；死锁防护先例同款；SYSTEM_CONFIG×2 为种子连带的既有空洞——菜单挂 SYSTEM_CONFIG 走派生则管理员必须持有其操作位，T-FE-022 联调同样受益）
4. **侧栏渲染 = 后端树直接渲染**（标题/图标/层级/排序全来自 sys_menu，一次到位：将来菜单管理页改表即生效，无二次接线返工；转换器补齐 parentId/pathList 满足侧栏组件契约）
5. **会话恢复失败态 = 侧栏重试占位项**（「菜单加载失败，点击重试」→ /menu-retry 极简重试页）
6. **多租户选择器不纳入**（维持固定租户 "1"，另立任务）
7. **Gateway 接口注册 = bootstrap 扩 20 条精确端点**（联调暴露：未映射路径 fail-closed 403，端点级粒度对齐产品 API 级授权能力；后续联调任务按页同样扩展）
8. **默认组织树 = bootstrap 种子**（联调暴露：/user/page 与 member-candidates 均为默认树身份目录视图，无默认树配置则用户列表恒空且创建端点无 UI——空库首用死锁）+ admin 挂根组织（身份目录开箱可见）

## 范围

### 后端（access-service，bootstrap 固定图扩展）

- `BootstrapGraphDefinition.businessGrants()` +18 条（操作码常量：ORG 系/USER 系取 `AdminOperationCode`，SYSTEM_CONFIG 取 `OperationCodeConstants.VIEW/MANAGE`；DDL 种子齐全零缺码——ORG 扩展码组 L855-861、USER ENABLE/RESET_PASSWORD L864-865、SYSTEM_CONFIG:MANAGE L895）
- `AccessBootstrapInitializer.GRANT_RESOURCE_TYPES` 补 ORG、SYSTEM_CONFIG（USER 已在）
- 菜单种子：固定图新增 15 行期望（1 纯展示 + 1 DIR + 13 资源挂接 MENU）；写入通道 = `MenuDomainService.insertBatch` 直接写表 + `LocalProjectionDomainService.upsertAdminMenu` 投影（幂等）；检测 = path 集合两态判定（全存在且结构键匹配→no-op；部分存在→冲突；全不存在→创建）
- `AccessBootstrapPgIT` 断言：授权总数/scopeAll 计数更新、快照表加 sys_menu、菜单行+投影行计数断言

### 前端（frontend）

- api 层契约对齐（acceptance 第 1 条清单）+ member-candidates 新增接入
- menus 接线：`initRouter` 重构（重取/复用/失败三分支）+ 后端树→侧栏菜单转换器 + permission store wholeMenus 数据源切换 + /menu-retry 重试页 + 失败占位项
- 调用方适配：getOrgTree 删 operationCode/treeConfigId 传参、角色分配/回收走新 perm 契约、组织编辑禁改 orgType、PositionTab parentOrgName 本地映射、UserForm 初始密码真实返回
- mock/user-manage.ts 删除

### 不做什么

- 不改 `filterNoPermissionTree`（T-PERM-037 定案；后端树直接渲染后该函数仅剩静态构建路径，不再是侧栏数据源）
- 不做多租户选择器（定案 6）；不动 mock/login.ts（开关 false，T-FE-041 遗产保留）
- 不改静态路由注册与页面代码的门禁逻辑（菜单不可见 ≠ 路由不可达，后端 403 兜底维持）
- 不动 DDL 种子（18 码全部已有种子；未来新码的权威位置是 DDL 扩展组，非 bootstrap 运行时造码）

## 联调验收场景

1. 空库 bootstrap → 登录首管理员 → 侧栏显示 15 菜单（全派生可见）——✅ 实测通过
2. 组织与用户页：组织树加载、组织 CRUD、用户分页/创建（含 orgId 一步入组+初始密码返回）/编辑/删除/启停/重置密码、成员挂载/移除/设主、岗位 Tab、角色分配/回收——✅ API 层 22 端点全实测 + 浏览器页面数据验证
3. F5 刷新 → 菜单恢复（重取）；模拟后端停机 → fail-closed 空菜单+重试占位 → 恢复后重试成功——✅ 实测通过（停 Gateway → F5 → 占位项 → /menu-retry → 重试恢复 15 菜单）
4. 无授权用户（BASIC_ROLE）登录 → 侧栏仅纯展示菜单，业务菜单不可见，直达 URL 后端 403——API 层门禁已验证（未注册端点 fail-closed 403、未授权操作码 403 兜底链在案）；浏览器双账号场景未单独走（权限派生链与场景 1 同构）
