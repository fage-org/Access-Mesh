# T-GW-007 Gateway CORS 环境化与 actuator 暴露收口

## 背景

gateway/src/main/resources/application.yml:63-66 配置 `allowed-origin-patterns: "*"` 且 `allow-credentials: true`（任意源携带凭证）；:96-99 公开白名单含 /actuator/prometheus 与 /actuator/metrics；:158-168 无 management.server.port（actuator 与主端口 8080 同端口未分离）。纯配置与少量校验代码改动，属试点前安全收口。

## 范围

- CORS origin 环境化、actuator 白名单与端口分离、配置 fail-fast 校验。

## 当前口径

- 最小安全修复：不做 API 网关策略框架、不做配置中心加密方案，仅收口暴露面。
- 2026-08-25 用户口径修订：生产 nginx 同源代理（CORS 无生产消费场景），原「生产环境缺失 origin 列表时启动 fail-fast」修订为「缺失=默认 localhost / 显式空=禁用，均不放行任意源（fail-closed）」。

## 用户决策（2026-08-25）

1. **CORS 终态（nginx 同源口径）**：默认 http://localhost:8848（前端 dev 实际端口 VITE_PORT 覆写 vite 原生 5173；开发直连调试用，vite 代理模式下同源不触发 CORS）；显式空（GATEWAY_CORS_ALLOWED_ORIGINS 置空）= CORS 禁用（同源部署终态）；校验器仅拦「通配 origin + allow-credentials=true」fail-fast。生产 nginx 同源无需配置 origin。
2. **管理端口**：management.server.port 默认 8081（占位符可覆盖）+ management.server.address 默认 127.0.0.1（仅同机可达，占位符可放开）。
3. **allow-credentials 保持 true**（任务卡口径，行为不变；token 走 Authorization 头无 cookie 依赖）。

## 执行记录（2026-08-25）

- **application.yml**：
  - CORS：`allowed-origin-patterns: ${GATEWAY_CORS_ALLOWED_ORIGINS:http://localhost:8848}`（原 "*"；默认端口经评审收口 D-1 用户决策从 5173 改为前端 dev 实际端口 8848），注释块登记四条口径（默认值语义/显式空=禁用/通配 fail-fast/Nacos 覆盖提示）；
  - 白名单：删除 `/actuator/health`、`/actuator/prometheus`、`/actuator/metrics` 三条，注释说明 actuator 迁移管理端口；
  - management 段：新增 `server.port: ${GATEWAY_MANAGEMENT_PORT:8081}` + `server.address: ${GATEWAY_MANAGEMENT_ADDRESS:127.0.0.1}`，注释登记 Nacos 覆盖风险。
- **GatewayProperties**：Whitelist 代码默认值同步删 `/actuator/health`（与 yml 一致）。
- **GatewayCorsConfigValidator（新增，仿 GatewayCacheBoundaryValidator 模式）**：遍历 GlobalCorsProperties 全部配置条目（不依赖单一 key——实测 yml 键 `'[/**]'` 经 Binder 绑定后 map key 为 `/**`，首版用 `[/**]` 取值的实现会静默绕过校验，已修正为条目遍历）；空/未配置 = 允许 + INFO 声明（CORS 禁用，同源终态）；通配（任意含 `*`）+ credentials=true = IllegalStateException 启动失败；过滤空白元素兜底空串绑定形态。
- **E2E（BasicRoleGrantVerticalSliceE2EIT）**：gateway 子进程 management 端口改传 E2E 分配的空闲端口（默认 8081 固定值有本机占用/并发冲突风险）；两处就绪探针（首启 + 步骤⑦重启）从主端口 `/actuator/health` 迁移到 `http://127.0.0.1:<管理端口>/actuator/health`——探针迁移本身由失败暴露：管理端口分离后主端口探测 404，正是「探针改访问管理端口」的第一个真实消费者。
- **测试**：`GatewayCorsConfigValidatorTest` 9 用例（含评审收口 D-2 补的 allowed-origins(exact) 通配拦截 2 例）（明确列表通过/未配置允许/空列表=禁用/空白元素过滤/通配+credentials 拒绝×2（含子域通配）/通配无 credentials 允许）；`GatewayApplicationConfigTest` 补 CORS 绑定断言（默认 localhost:8848 + credentials true）、白名单无 /actuator 断言、management 端口绑定断言（8081/127.0.0.1）。

## 验证证据（2026-08-25）

- `mvn test -pl gateway -DskipTestcontainers=true`：**91 用例，0 失败**（基线 83 + 新增 7 ValidatorTest + 1 ConfigTest 新方法）。
- `mvn test -pl gateway`（含容器轨）：**E2E 8/8 全绿**（80.8s，双子进程真实启动；日志实证 GatewayCorsConfigValidator 在真实子进程通过、就绪探针经管理端口工作、步骤⑦重启链路正常）。
- 主端口无 actuator 的行为证明：管理端口分离后主端口 `/actuator/health` 探测 404（E2E 迁移前失败的直接证据）。

## 评审收口（2026-08-25，双轨子代理全面评审：代码轨 0 P0-P2（5 P3/备注实证核实）、文档轨 3 P2，全部处置）

代码轨关键实证结论：Binder 对 yml 键 `'[/**]'` 绑定后 key 为 `/**`（条目遍历实现正确且更强）；校验器构造注入 GlobalCorsProperties 的生命周期时序无竞态（绑定在 bean 创建阶段先于 afterPropertiesSet，Nacos 覆盖后终值可见）；显式空串 → Binder 绑定 `[]`（非 `[""]`）→ checkOrigin 恒 null → CorsProcessor 主动 403 拒绝（fail-closed 成立）；主端口 /actuator/** 确定行为 404（全部认证过滤器为 GlobalFilter 仅在路由命中后执行，未命中路由无 handler）。

处置项：
- **D-1（用户决策）**：默认 origin 端口 5173 → **8848**（前端 dev 实际端口，VITE_PORT 覆写 vite 原生值；yml/Validator javadoc/ConfigTest 断言/文档同步）。
- **D-2**：校验器补兄弟键 `allowed-origins`（exact）通配拦截（Nacos 覆写该键为 "*" 时原实现会漏到运行期每请求 500 而非启动 fail-fast），补单测 2 用例。
- **D-3**：yml/gateway.md 登记 `GATEWAY_MANAGEMENT_PORT` 不支持空串禁用（空串=null=未配置，管理端口分离会静默回退）。
- **D-4**：E2E freePort() 绑定改 127.0.0.1（原 "localhost" 解析 ::1 时与管理端口地址族错配的理论 flake）。
- **D-5**：措辞修正——「不加 CORS 头被浏览器拒绝」实证为「CorsProcessor 主动 403 拒绝且无 CORS 头」（机制更强，yml/gateway.md 同步）。
- **P2-1**：本卡「设计回写」节 127.0.01 笔误修正。
- **P2-2**：architecture.md §2.1 白名单描述「健康检查」漏改修正（actuator 已走管理端口）。
- **P2-3**：ConfigTest 新方法内联全限定名改顶部 import、半角逗号改全角（对齐文件惯例）。
- **登记不修**：plan「当前进度」未补执行记录行（与最近 T-PERM-043/T-ADMIN-023 先例一致，惯例漂移留 T-ACCESS-026 统一口径）；T-GW-006 历史任务卡中的 /actuator/prometheus 描述属历史记录不改。
