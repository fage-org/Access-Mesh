# T-FE-059 共享列表上下文与可写对象绑定

## 背景

承接[评审证据](../archive/2026-09-20/comprehensive-review.md)的 F011（已知stale问题新增影响）；基线与静态/动态证据强度见该记录。

## 范围

- useListLoad上下文键与代际；service-interface、resource-operation及同模式调用方的切换、清空、失败、表单提交。

## 当前口径

方案唯一入口：[IAM闭环方案](../design/iam-task-closure.md#list-context)（§4.4 已转已实施，实施定案与用户拍板见该节及 registry 2026-09-23 T-FE-059 行）。

**启动拍板（2026-09-23）**：保存时上下文核对层**加**——主触发面由「切上下文即清空旧行」结构性闭合后，残余窄路径（浏览器后退键+全局弹窗跨路由常驻+重进页面提交旧弹窗）按「行/弹窗自带上下文 vs 当前选中上下文」比对堵死；UserDetailPanel 显式目标操作不绑（表单权威模式，见遗留节）。

## 验收对照

- ✅ 验收①：切上下文取数发起即清空旧数据（loader contextKey），失败/清空/权限失效不回填（clear() 作废在途+短路分支走 clear）；保存前逐入口核对目标上下文，不一致拒绝且不发货——hook spec 断言「不残留/不发货」。
- ✅ 验收②：同上下文刷新失败保留旧数据（composable 用例锁）；浏览器证据含失败后重试恢复（截图 03）。
- ✅ 验收③：service-interface/resource-operation/user 真实 hook 复现用例由失败变通过（红跑实证）；浏览器切换失败/重试证据三截图入仓 `docs/tasks/evidence/t-fe-059/`（dev 栈 vite 8890 + playwright Edge headless + route.abort 模拟 B 加载失败；验收过程 admin 密码哈希临时替换后已还原、evidence 服务与映射行已清理）；后端零改动，守卫为前端前置拒绝。
- ✅ 验收④：类推面闭合——service-interface 明细/resource-operation 树+操作表/user 成员表接 contextKey、PositionTab watch 预清空+自有代际；biz-domain 子表与 MappingForm 既有「切换预清空」先例达同语义维持不动；仅扩 useListLoad/usePagedList（contextKey/onClear/clear），未新增状态框架。

## 非目标 / 遗留

本卡只覆盖上述闭环，不自动扩展相邻产品能力；已有暂缓事项仍沿原任务。新发现且不能在本卡收敛的独立事项按项目生命周期登记，禁止把未知结果写为完成。

- UserDetailPanel 的角色授予/组织挂载操作不绑组织上下文（拍板口径：操作目标为弹窗内显式选择的显式 userId，表单权威模式无上下文错位；后续若交互形态改变随触达任务重估）。
- PositionTab `loadPositionUserCount` 无代际守卫：切组织后迟到计数写旧组织 id 键，无 UI 影响（新组织列表不含旧 id、切回旧组织被重拉覆盖）——T-FE-057 遗留形态，随轻量清扫批次定夺。

## 完成记录

2026-09-23 收口。实施与定案详见 [iam-task-closure §4.4](../design/iam-task-closure.md#list-context) 实施口径段与 [registry 2026-09-23 T-FE-059 行](../design/decision-registry.md)。要点：

- **加载器扩展**：`useListLoad`/`usePagedList` 新增可选 `contextKey`（getter，null=合法上下文值）+ `clear()`（清空并作废在途）+ `onClear`（分页 total/page 复位）；为不同上下文取数发起即清空，切换后失败不回填，同上下文刷新失败保留旧数据；`hasLoadedContext` 区分「null 已加载」与「从未加载」（双轨评审 P1 处置：哨兵归一旧形态在用户页全组织视图漏清空，已修）。
- **消费面**：service-interface 接口映射明细（选中服务）、resource-operation 资源树+操作表（选中类型；权限/类型置空短路走 clear 作废在途，短路同步重置 selectedNode）、user 成员表（选中组织，usePagedList）、PositionTab（watch 预清空+自有 positionReqSeq，切组织同步清 positionUserCounts）。
- **保存时核对层（拍板「加」）**：映射编辑/删除（行 serviceCode）+新增弹窗快照（openedAtServiceCode，收必传——claude 外评处置对齐 handleUpdate 先例）、资源编辑/删除/移动、操作权限编辑/删除（resourceTypeCode）、用户更新（必传 openedAtOrgId）/删除/启停/重置密码、岗位编辑/删除（props.orgId）——不一致拒绝提示、不发请求、开关/弹窗状态回滚；守卫覆盖面按入口枚举核对（不计数，claude 外评处置去计数化）。
- **验证**：新增 22 用例（21 个旧实现下红跑实证：loader 层 4+F011 形态 2+用户页 3+守卫 12；1 个为同上下文保留语义锁）；`pnpm test` 432/432（2026-09-23）、`pnpm typecheck`/`pnpm lint`/`pnpm build` 全 0；浏览器证据 ALL PASS（登记第二服务→A 加载→切 B 失败清空+toast→重试恢复，截图 01/02/03）。
- **双轨评审处置**：代码轨 P1（null 哨兵归一）/P2（submitMove 守卫）直修并红跑实证，P3×5（selectedNode 复位/positionUserCounts/新增弹窗守卫/openedAtOrgId 必传/计数勘误）全处置；文档轨 P2 同源+P3×4（注释措辞/背景句时态/registry 登记/启停注释限定）随批收敛；过度设计可裁剪项=0。
