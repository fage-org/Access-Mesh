# T-GW-010 开发与代理拓扑的 Origin 接入一致性

## 背景

承接[评审证据](../archive/2026-09-20/comprehensive-review.md)的 F012（quickstart 推荐避让端口与 Gateway CORS 默认白名单矛盾 + 常见问题表错误归因）；基线与静态/动态证据强度见该记录。

## 范围

- quickstart开发端口/域名/Gateway允许Origin的完整示例和错误定位；Vite与nginx支持拓扑核验。

## 当前口径

方案唯一入口：[IAM闭环方案](../design/iam-task-closure.md#cors)。实施定案（2026-09-23 用户拍板，registry 同日行）：

- Gateway CORS 默认白名单扩为四个环回 dev 形态（`http://localhost:8848,http://localhost:8890,http://127.0.0.1:8848,http://127.0.0.1:8890`）——F012 实证 8890 避让形态被旧单条默认 403 空体拒，`localhost` 与 `127.0.0.1` 按字面各占一条；`GATEWAY_CORS_ALLOWED_ORIGINS` 设值=整体替换默认四条。
- 前端 dev 默认端口维持 8848（不改），quickstart「VITE_PORT=8890 避让 Nacos」指引保留并补 CORS 说明。
- T-GW-007 定案段「开发经 vite 代理同为同源」前提修正为 Gateway 视角跨域（`changeOrigin` 只改写 Host 不删浏览器 Origin；环境化/置空禁用/通配 fail-fast 三项定案未动）。
- quickstart 常见问题表重写为三列可区分诊断表，修正「CORS 403=未走 Gateway」错误归因。

## 验收对照

唯一验收清单见 frontmatter `acceptance`；逐条证据见完成记录。
