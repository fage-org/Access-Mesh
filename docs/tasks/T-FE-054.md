## 背景

2026-09-19 外评降级项「token 过期放行系 T-FE-041 明文口径」转出：本地 `expires` 到期时请求拦截器调 logOut 后**本次请求无令牌照常发出**，靠 Gateway 返回 401 再触发响应拦截器二次 logOut——多一次必然 401 的往返，且全程零提示（用户莫名回登录页）。

## 四项用户拍板（2026-09-20，AskUserQuestion 四问，定案见 decision-registry 同日行）

1. **Q-016 随本卡收口，修法=注销改 fire-and-forget**（弃「保留 await+代际守卫」与「维持不修」）：logOut 捕获令牌后 logout 请求发出即不等，本地清理+跳转立即执行——挂起与新登录凭据竞态同时消除；代价=T-FE-045「服务端注销优先」从「等注销完成」演进为「请求已发出即清理」。refreshSessionCapability 补 single-flight（同会话并发共享在途 Promise）+代际守卫。
2. **Q-020 随本卡收口**（弃「留给 T-FE-056」）：initRouter（会话恢复统一入口）加无凭证分支——判定挂统一入口而非页面单点判 token，符合 2026-09-19「统一处理」口径。
3. **双分支统一提示**「会话已过期，请重新登录」：本地过期短路与响应 401（服务端冻结/他端登出）同结局同语义。
4. **页面层照弹**：短路 reject Error（message 与提示同源）由 toErrorMessage 透出，与 401 现状「页面弹错+跳登录」一致，不做静默标记。

## 实现落点（2026-09-20）

- `src/utils/session-expired.ts`（新增）：`notifySessionExpiredOnce`（10s 去重窗口，三通道共用）+ `SessionExpiredError`；独立小模块——去重状态放 http 会新增 router/utils→http 反向边成环、放 router/utils 属职责错位。
- `src/utils/http/index.ts`：请求拦截器过期分支 resolve 放行改 reject 短路（提示+logOut+reject 同文案 Error）；响应拦截器 401 分支补统一提示（与短路共用去重窗口）。白名单三端点（captcha/login/logout）不做过期判定不变。
- `src/store/modules/user.ts`：logOut 注销 fire-and-forget（失败 console.warn 不弹错）；refreshUserMenu 前后按 accessToken 指纹代际守卫（成功回写〔Pinia+localStorage userKey〕与失败置位均拦截）。
- `src/router/utils.ts`：refreshSessionCapability 入口内共享在途 Promise（同 fingerprint 复用、finally 判 promise 同一性复位）+ rebuild 前代际二重守卫；initRouter 开头无凭证分支（提示+logOut+throw SessionExpiredError，守卫/登录路径必有凭证不触达）。
- `src/views/error/menu-retry.vue`：retry() 加 catch——统一层已提示+跳登录，不再弹「仍无可用菜单/仍失败」失真业务提示。
- 回归锁：http/index.spec 新 describe（短路零请求/并发只弹一次/401 提示/窗口跨分支去重/白名单与未过期特征锁）；user.spec（fire-and-forget 主锁重写〔红跑态 try/finally 收尾防 logoutInFlight 残留污染〕+代际×2 含 userKey setItem 断言）；router/utils.spec（无凭证锁+有凭证特征锁+single-flight/代际/复位三锁，mock 全链+resetModules 隔离模块级状态）。红跑实证（stash 源码对旧实现）：**10 红/28 绿**——10 把新锁全红，特征锁与既有锁不误伤。
- vitest 348/348 + typecheck/lint/build 全 0。
