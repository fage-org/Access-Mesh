## 背景

P2×4 + P3×1 批（外部持续审查发现，2026-10-14 主代理核实成立）：

- **迟到 401 注销新会话**：旧租户请求的迟到 401 会把刚建立的新会话注销（用户重登竞态）。
- **会话终结残留弹窗**：会话终结清了令牌但保留全局编辑弹窗及旧上下文，旧对象可继续被提交。
- **组织树配置乱序**（P2，探针实证真实 SFC 复现）：`ReOrgTreePanel` 的 loadTree/onConfigChange 在 await 后直接覆盖 rawOrgTree 并 emit org-change，无请求代际或配置身份校验；20→30 连续切换、30 先回 20 后回时，目录与选中组织被旧配置覆盖，右侧用户列表筛选随之错域。
- **重置密码重入**（P2，探针实证）：`MemberTab.vue` handleResetPassword 确认→await→弹密码全程无同用户互斥；A 写入后响应慢、B 再确认且先返回时，A 迟到弹窗交付已失效密码。
- **改密 OAuth 续接丢失**（P3）：`change-password/index.vue` 成功路径带 returnTo 调 logOut，`utils/http` 401 分支无参 logOut 落裸 /login——首请求已成功但响应超时→重试 401→重登后不回原授权确认地址。

## 范围

五个时序缺陷的前端守卫；后端行为不动。

## 当前口径

复用现有代际/序号守卫模式（useListLoad 同款）与局部 pending 状态；不新增请求取消框架、目录状态平台、密码历史表或交付平台。034 仅承接经 oauthReturnTarget 白名单校验的本地目标。

## 验收对照

见 frontmatter `acceptance`；组织树乱序与重置密码反序两例须在旧实现下失败（探针已提供可转正的复现形态）。

## 非目标 / 遗留

## 完成记录（2026-10-15）

**两项拍板**（决策提问协议，场景+示例+后果呈现）：①续接规则落点=方案 A（logOut 缺省继承当前页 returnTo，经 oauthReturnTarget 白名单校验；401 分支/本地过期短路/initRouter 三终结通道统一，顶栏主动登出实测不受影响——改密页/登录页均为无布局全屏页）；②重置密码跨标签页/跨操作员形态无法纯前端检测（服务端响应无代际标识）→ 登记 [Q-081](../pending-problems.md) 待盘点。

**实现**（五处守卫 + 一项基建拆分）：

1. **迟到 401 代际守卫**（`utils/http/index.ts` 401 分支）：401 只终结其所属会话——请求携带的 Authorization 头与当前令牌一致才提示+logOut（平台分支同款比对先例）；重登/换租户后旧请求的迟到 401 不注销新会话；令牌已清（getToken 空）维持既有幂等口径（不提示、仍 logOut 兜底），既有外评 P3 用例零改动通过。
2. **会话终结清全局弹窗 + returnTo 缺省继承**（`store/modules/user.ts logOut`）：本地清理段增 `closeAllDialog()`（dialogStore 为模块级全局、ReDialog 挂 App 层 router-view 之外——登出不清则旧上下文弹窗浮在登录页、重登后旧对象仍可被提交；直清不触发弹窗回调，终结处置不做保存类副作用）；跳登录前 `oauthReturnTarget(returnTo ?? router.currentRoute?.value?.query?.returnTo)`。**基建拆分**：弹窗队列自 ReDialog barrel 拆出纯 ts `ReDialog/store.ts`（dialogStore/addDialog/closeDialog/updateDialog/closeAllDialog），barrel 原样再导出、index.vue 改依赖 store.ts 与 type.ts（顺带解除原 index.vue↔index.ts 环）——会话终结方依赖链不含 SFC，node 测试环境（无 vue 插件）全仓 spec 不再需要 mock 弹窗模块。
3. **ReOrgTreePanel 竞态守卫**：树/选中生命周期自 SFC 抽出 `src/model.ts`（`createOrgTreeModel`，形态对齐 oauth-consent/model.ts）——loadTree latest-wins 代际（迟到成功/迟到失败均静默丢弃，含重定位与 org-change 副作用）；switchConfig 跨配置发起即清旧树+`org-change(null)` 通知消费方并同刻作废在途；SFC onConfigChange 续接前配置身份守卫（等待期间又切配置则本次自动选中作废）；交互层（高亮/popover/node-click）留组件，defineExpose 面（orgTree/selectedOrgId/selectedConfigId/loadTree）不变。
4. **重置密码同用户互斥**：流程自 MemberTab 抽出 `utils/reset-password.ts`（`createResetPasswordFlow`）——pending reactive Set 登记（入口登记/finally 复位，覆盖确认→请求→交付全程），在途期间同用户再触发入口即拒（warning「该用户的密码重置正在进行中，请稍候」）；`isPending` 同源驱动行内按钮与 dropdown item 的 disabled；T-FE-059 上下文漂移守卫（openedAtOrgId 核对）语义原样保持。跨 tab 形态=Q-081。
5. **改密 OAuth 续接**：change-password 成功分支显式传参不变；401 分支/短路/initRouter 无参 logOut 缺省继承（拍板 A）——重试 401、登录页 user-menu 401、改密页本地过期短路三旁路的 returnTo 丢失一并消除。

**红跑取证**（旧实现下 7 项行为红，2026-10-15 vitest 报告）：model.spec 3 红（锁①迟到成功覆写新树/锁②跨配置预清空缺失/锁③迟到失败清树+弹错——model.ts 先以旧逻辑移植为红跑载体）；user.spec 2 红（returnTo 缺省继承裸 /login/closeAllDialog 零清理——后者在 mock 形态红跑后改 store-real 断言形态并以注释掉 closeAllDialog() 复跑再证红 1 项）；http spec 1 红（迟到 401 仍 logOut）；reset-password.spec 1 红（同用户二次触发照发请求）。首轮另 1 红（「不同用户不互斥」）为测试自身缺陷（await 未 resolve 的 defer）已修正——修正后旧实现下绿，属特征锁。特征锁（重定位 keep/clear、不同用户不互斥、取消路径、上下文漂移、白名单外不继承、当前会话 401 照常终结）旧实现下全绿——锁语义非锁修复。
