# T-FE-016 Phase 3 联调：角色管理

> 状态：done（2026-09-01 单日收口；任务卡为启动时补建——phase3-plan 任务行只留标题，详细范围入卡）

## 背景

Phase 3 第二个联调任务。前置事实（调研核实，2026-09-01）：

- api 层（`frontend/src/api/role-manage.ts`）在 T-FE-041 已切真实路径（`/perm/api/perm/abstract-role/*` + PermResult 信封解包）——本任务主体不是切路径，而是 Gateway 注册补齐、编辑回显接线与 mock 退役
- 页面活跃消费 5 端点（tree/create/update/move/remove）+ 本任务接入 detail；其中 tree/create 已在 bootstrap Gateway 清单，update/remove/move/detail 未注册（未映射路径 fail-closed 403，写操作全打不通）
- extra-roles 三封装（listExtraRoles/addExtraRole/removeExtraRole）不可达保留（T-PERM-043 既定：GROUP_ROLE 写入口已删、类型隐藏，恢复 role_inclusion 立项时随 MANAGEABLE_ROLE_TYPES 放开）
- mock/role-manage.ts 拦截旧 `/api/perm/**` 路径，对现路径自 T-FE-041 起自然失配；全仓零 import（mock/login.ts 角色矩阵独立取自 perms.ts SSOT，不受删除影响）

## 设计定案（2026-09-01，经用户决策）

1. **编辑 extra 回显 = detail 回填**：树节点契约不含 extra 字段，编辑表单直接拿树节点回填 → extra 回显空白（后端 update null=不更新语义保证不误删，但旧值不可见、无法从界面清空；mock 时代树节点带 extra 故从未暴露）。修法=编辑弹窗打开时按业务键拉 `/detail` 回填（页设 §8 处置行与 RoleTreeNode 类型注释两处明示的设计意图）；备选（树节点补 extra 字段/维持现状登记）经决策弃用
2. **开发库现在重建**：Gateway +4 端点改变固定图定义，既有开发库重启即 fail-fast（幂等三状态不自动补权）；按 runbook 重建（DROP SCHEMA 重跑 DDL + 清 Redis + 重启 access-service），冒烟数据现造
3. **extra 清空协议 = extraClear 显式标志（对齐 T-PERM-028 资源域标准方式）**：冒烟实测暴露「清空 extra 无协议通道」——前端空串提交转 null、后端 null=不更新，清空意图无法表达。资源域 update 已有 extraClear 布尔标志成文（契约 §5.3）且前端资源页在消费，角色页同构接入保持全仓单一清空协议

## 已知差距（登记，不在本任务范围）

- **extra 无 JSON 校验直达 PG 500**：编辑/创建表单均无 JSON 语法校验（placeholder 提示「JSON 格式」但 rules 只含类型/名称/外部标识），后端 create/update 亦无预校验（biz-domain 域有 `JsonValidationUtils` 预校验先例，T-PERM-026）——非法 JSON 文本直达 `abstract_role.extra JSONB` 列报 500。前端规则或服务端校验属后续加固（资源域 `ResourceForm` 同款缺口一并考虑）
- **SDK Feign `getRole` 契约漂移（T-PERM-022 遗漏同步，非本任务引入）**：`perm-client PermissionFeignClient.getRole` 仍声明 `IdReq`，而控制器 `PermRoleController.getRole` 已是 `RoleDetailReq` 业务键二元组——SDK 消费方调用 detail 会因请求体形状不符失败；待 SDK 债务任务收口（本任务无 SDK 副本需同步，`RoleUpdateReq`/extraClear 无 SDK 副本）
- **bootstrap-admin 自我锁面（评审存疑，经用户决策维持现状）**：角色写保护仅拒本地投影角色（`rejectIfLocalRole`），bootstrap-admin 属 BASIC_ROLE 手工角色可改名/清空/删除——本任务把 update/remove/move 注册进 Gateway 后该能力首次从管理 UI 可达，删之即失去唯一种子管理角色（需重建库恢复）；「管理角色也是角色」为 T-PERM-022 既定语义，误删风险由租户自担（rebuild 流程可恢复）

## 联调验收场景

1. 重建库 bootstrap → 登录 admin → 角色树加载（bootstrap-admin 基础角色）
2. 创建 BASIC_ROLE（externalId 必填 + extra 填值）→ 树中出现
3. 编辑该角色 → extra 回显旧值（detail 回填）→ 修改保存 → 再开确认新值；清空保存 → 再开确认为空（extraClear）
4. 启停切换（禁用角色仍在树可见可再启用——T-PERM-022 树全量语义）
5. 删除角色 → 树中消失
6. 拖拽移动：同类型父子合法；跨类型拖拽前端拦截（allowDrop + 后端 20022 兜底）
