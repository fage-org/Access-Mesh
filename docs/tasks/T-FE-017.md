## 背景

Phase 3 第三个联调任务。前置事实（调研核实，2026-09-02）：

- api 层与页面接线在 T-PERM-028/T-FE-041 已就位（真实路径、业务键定位、编辑 extra 回显按 detail 回填、extraClear 本页即首例）——本任务主体是 Gateway 注册补齐、业务门禁补齐、mock 路由段退役与联调冒烟
- 页面消费 11 端点（资源 tree/create/update/move/remove/detail + 操作 list/create/update/remove + 类型定义 list），已注册仅资源 tree 与操作 list（类型定义 list 先在册），写路径全 fail-closed 403
- 后端门禁：RESOURCE:VIEW/CREATE（类型级）、RESOURCE:MANAGE（实例级）、OPERATION:VIEW/CREATE/MANAGE（类型级）；固定图原持 VIEW 两条，CREATE/MANAGE 四条缺失（不补则空库写操作无授予起点，死锁）
- mock/resource-operation.ts（822 行）与 T-FE-016 的 role-manage 情形不同：数据导出仍被三个未联调页面的 mock 引用，不能整删

## 设计定案（2026-09-02，经用户决策）

1. **mock 处置 = 删路由段保数据导出**：11 个 fake-server 路由自 T-FE-041 切真实路径起已失配（死代码），删除；resources/operations/InternalResource/presetOperationsForType 数据导出保留（resource-dependency/type-def/permission-grant 三 mock 仍引用，其页面联调任务 T-FE-018/020 等未开始），届时随各自 mock 退役一并处置。备选（保留整文件+注记/整删并改造三个依赖 mock）经决策弃用
2. **开发库现在重建 + 浏览器冒烟**：固定图 +8 端点/+4 门禁变更，既有库重启 fail-fast；按 runbook 重建后冒烟（T-FE-016 先例）
3. **dev 密钥四变量换新值**（用户指示「你生成即可」）：ACCESS_BOOTSTRAP_ADMIN_PASSWORD/JWT_SECRET_KEY/ACCESSMESH_SIGNATURE_SECRET/PERM_INTERNAL_SECRET 全部新生成，Gateway 随 access-service 一并以同值重启（两密钥必须两侧同值）
