# T-FE-043：权限排查页（permission-query）重做——暂停期问题与功能登记

> 状态：proposed（2026-09-06 用户定案：**页面整体暂停，后续重做**；定案已登记 decision-registry）
> 依赖：无硬依赖（重做启动条件=用户拍板）

## 暂停定案（2026-09-06）

T-API-002 执行中就「query-scopes 响应裁剪后排查页展示形态」提问，用户决策：**排查页的问题和功能先记录，页面暂停，后续整体重做**。定案登记见 `docs/design/decision-registry.md` 2026-09-06「权限排查页暂停待重做」条目（同日「SDK 直连端点内部 id 全线裁剪」条目为关联契约面定案）：暂停期内其他任务对本页只做编译一致的最小改动，不投入页面改造；评审不报本页 UI/交互缺陷，改登记到本卡。

## 暂停期已发生的最小改动（T-API-002，2026-09-06）

- `frontend/src/api/permission-query.ts` / `frontend/src/api/perm-scope.ts`：`QueryScopesResp.parentPermissionIds`、`ScopeGroup.matchedRoleIds/matchedPermissionIds/dependOnPermissionIds`、`ResourceEntry.matchedRoleIds/matchedPermissionIds` 类型字段随契约裁剪清除。
- `frontend/src/views/system/permission-query/components/ScopeMatrixPanel.vue`：信息条「主权限ID」栏随 `parentPermissionIds` 删除（三栏改两栏：匹配主操作 | 缓存TTL）。

## 重做时需考虑的已知事项（暂停期累积登记）

- **契约面**：query-scopes/query-resources 响应已裁内部 id 字段族（T-API-002）且维持该终态——check 族的裁剪已被 T-API-003（2026-09-10）推翻恢复全量回传，但本页消费的 Query\* 响应族不受影响；重做时来源类展示应走业务键先例（explain 的 `sourceRoles`：roleTypeCode + roleExternalId + roleName + via）。
- **端点选型待重议**：本页 Tab2 直接复用运行时端点 `/api/perm/auth/query-scopes`（§6.7 运行时语义无排查门禁 + 页面级 UI 门，T-PERM-033 定案）；重做时是否继续复用或换 §6.8 排查端点是重做设计决策。
- **类型双轨待收口**：`api/perm-scope.ts`（T-PERM-015 类型基础，当前零导入方）与 `api/permission-query.ts` 内联类型定义重复维护同一契约，重做时应二合一。
- **既有能力基线**：T-FE-019 收口的 explain 扩展展示（context.clientIp 模拟、conditionEvaluations 脱敏明细、conflictDrops）与 recentChanges 权限键过滤已接线，重做保留能力不回退。
