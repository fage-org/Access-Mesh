## 设计定案（2026-09-02，经用户决策）

1. **mock 处置 = 按 T-FE-017 先例**：conflict-rule.ts 整文件删除；permission-condition.ts 删路由文件、保留 `_shared` store（授权页 mock 仍消费，T-FE-018 届时处置）。备选（保留死路由仅注记 / 连 store 一起删并改造授权页 mock——会扩大任务范围到 T-FE-018）经决策弃用
2. **description 清空语义 = 登记已知差距，本任务不动**：两页表单恒传 description 字符串（初始 ""），后端 update null=忽略——用户清空输入框写入空串而非 NULL，且无恢复 NULL 的协议通道。与 T-FE-016 extraClear 同族但 description 为普通描述文本、''/null 展示层无差别；引入 descriptionClear 四件套超联调范围，与 extra JSON 校验缺口同族待专项处理
3. **联调验证 = 重建库 + 浏览器冒烟**：固定图 +9 端点变更，既有库重启 fail-fast（runbook §3 登记模式）；dev 密钥沿用 T-FE-017 留存值不换新
