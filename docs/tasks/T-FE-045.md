> 状态：done（2026-09-19 收口）

## 背景

外评 P1（成立）：`useUserStore.logOut()` 注释明示「前端登出（不调用接口）」，只清 Pinia/localStorage/cookie 后跳 `/login`；后端 `POST /api/access/auth/logout`（AdminAuthController → StpUtil.logout）已存在且契约总册 §343 列入会话六端点，前端 `api/auth.ts` 连 logout 函数都未定义。用户点「退出登录」后，已复制出去的 Bearer token（同一 Sa-Token 会话）在服务端仍然有效。

## 范围

- `src/api/auth.ts` 新增 `logout()`：POST `/api/access/auth/logout`，经 `unwrap` 解包。
- `src/store/modules/user.ts` `logOut()` 改造：先调 `logout()`，无论成败都执行既有本地清理（state 清空、removeToken、multiTags 重置、resetRouter、跳 /login）；服务端失败仅 console.warn，不打扰用户（退出意图已明确）。
- 防抖：登出进行中重复触发直接短路（同一登出动作只发一次注销请求）。
- 登出 UI 入口（顶栏下拉）接线不变。

## 当前口径

服务端注销优先、本地清理无条件：注销请求失败不把用户留在系统内（浏览器本地凭证已清，后端会话按 Sa-Token TTL 自然过期）；也不因失败弹错误打断退出流程。

## 验收对照

见 frontmatter acceptance；回归锁写法对照 `user.spec.ts` 既有 mock 形态（mock http 层断言调用序）。

## 非目标 / 遗留

- 踢全部端点（logoutAll）与多设备会话管理——超范围，另行评估。
- 401 响应拦截器路径的 logOut 调用共享新实现（注销请求显式带 token 后该路径同样能完成服务端注销）；会话已被服务端判定失效时 POST /logout 为无害 no-op。

## 完成记录（2026-09-19）

- `api/auth.ts` 新增 `logout(authorization)`：POST `/api/access/auth/logout`，`R<Void>` 经 unwrap 解包；Authorization 头值由调用方显式传入原样送达（api 层纯透传，不耦合 utils/auth 的 store/router 链）。
- `utils/http/index.ts` 请求白名单纳入 `/api/access/auth/logout`（注释同步改写：白名单语义=不经拦截器令牌附加/过期判定；logout 入白名单防过期分支 `logOut` 递归，令牌由调用方显式携带照常送达）。
- `store/modules/user.ts logOut()` 改 async：模块级 `logoutInFlight` 串行防抖（进行中短路）→ `getToken()` 持令牌先 `logout(formatToken(token.accessToken))`（失败仅 console.warn）→ 本地清理无条件（清 Pinia → removeToken → multiTags 重置 → resetRouter → 跳 /login）；登出完成后重复触发时 getToken 已无令牌，零请求仅幂等清理+跳转。
- 回归锁 7 个（auth.spec×3：URL/方法/显式头透传、unwrap 抛 RequestError、白名单源码扫描；user.spec×4：调用序（POST → removeToken → resetRouter → push，显式传 `Bearer <token>`）、服务端失败仍清理、进行中短路单请求、完成后零请求），红跑实证：stash 三源码文件复跑，**7 新用例全红、7 既有用例全绿**。
- login.md 回写：「登出流程」新节（三性质+退役注记）+ 令牌生命周期两处 logOut 指针 + 组件结构/last_reviewed 更新。
