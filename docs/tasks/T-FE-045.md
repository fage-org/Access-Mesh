## 背景

外评 P1（成立）：`useUserStore.logOut()` 注释明示「前端登出（不调用接口）」，只清 Pinia/localStorage/cookie 后跳 `/login`；后端 `POST /api/access/auth/logout`（AdminAuthController → StpUtil.logout）已存在且契约总册 §343 列入会话六端点，前端 `api/auth.ts` 连 logout 函数都未定义。用户点「退出登录」后，已复制出去的 Bearer token（同一 Sa-Token 会话）在服务端仍然有效。

## 范围

- `src/api/auth.ts` 新增 `logout()`：POST `/api/access/auth/logout`，经 `unwrap` 解包。
- `src/store/modules/user.ts` `logOut()` 改造：先调 `logout()`，无论成败都执行既有本地清理（state 清空、removeToken、multiTags 重置、resetRouter、跳 /login）；服务端失败仅 console.warn，不打扰用户（退出意图已明确）。
- 防抖：登出进行中重复触发直接短路（同一登出动作只发一次注销请求）。
- 登出 UI 入口（顶栏下拉）接线不变。

## 当前口径

服务端注销优先、本地清理无条件：注销请求失败不把用户留在系统内（浏览器本地凭证已清，后端会话按 Sa-Token TTL 自然过期）；也不因失败弹错误打断退出流程。

## 验收对照

见 frontmatter acceptance；回归锁写法对照 `user.spec.ts` 既有 mock 形态（mock http 层断言调用序）。

## 非目标 / 遗留

- 踢全部端点（logoutAll）与多设备会话管理——超范围，另行评估。
- 401 响应拦截器路径的 logOut 调用共享新实现（注销请求显式带 token 后该路径同样能完成服务端注销）；会话已被服务端判定失效时 POST /logout 为无害 no-op。
