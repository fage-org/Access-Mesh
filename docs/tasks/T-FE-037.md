# T-FE-037 Phase 3 联调：权限授予（4.1）- 组织联调（二期）

> 状态：done（2026-09-04 收口）
> 依赖：T-FE-018（角色联调首期完成）+ T-ADMIN-021（org-tree includePositions，二期）
> 门禁：见 acceptance 第一条

## 背景

T-FE-018 已拆分为角色联调（首期，T-FE-018）与组织联调（二期，本任务）。组织入口依赖 T-ADMIN-021（admin-service org-tree 扩展 includePositions），首期不推进；T-ADMIN-021 done 后本任务启动，将组织入口 mock 切真实后端。

## 联调范围

- 接口：`org-tree`（includePositions=true，T-ADMIN-021）+ `role-resource-permission/list` + `apply-grant-plan`（唯一写入口）+ `extra-roles/list`
- 主通道：全部写操作统一走 `apply-grant-plan`（无 CAS/幂等表，单事务原子 + 受影响行数断言）
- 主体：组织（ORG）+ 岗位（POSITION）

## 设计口径

1. **主体树停用过滤（用户决策 2026-09-04）**：`getOrgTree({includePositions: true, status: 1})` 仅启用组织/岗位可作授权目标，对齐角色入口 `enabledOnly: true` 先例（T-PERM-022）；接受节点级过滤副作用——停用父组织下启用子树（含岗位）在本页不可见（后端 buildTree 按 parentOrgId 挂链，孤儿不挂；用户管理页组织树不受影响，不传 status）。
2. **入口按钮位置（用户决策 2026-09-04）**：组织与用户页（2.1）两处入口——顶部组织信息卡片「权限授予」按钮（预选当前选中组织）+ 岗位管理 Tab 岗位行操作「权限授予」（预选该岗位）；门禁均 ROLE:VIEW（§10 轨道 2 矩阵查看门禁，同角色页先例）。
3. **GrantContext 派生**：组织节点（orgType=1）→ `roleTypeCode: "ORG"`、岗位节点（orgType=2）→ `"POSITION"`、`roleExternalId = String(sys_org.id)`（对齐 abstract_role 投影 external_id，admin-service-api-contract §4.2.1 / LocalProjectionDomainServiceImpl.upsertAdminOrg）；`domainCode` 恒 null（P1-1）；岗位预设 query 与组织共用 `roleExternalId`（sys_org.id 全表唯一，findNode 不限定类型）。
4. **适配器形态（按设计 §9）**：SubjectTreePanel 组织分支内联适配器 + `subject-tree.ts buildOrgSubjectTree` 纯函数（新增 kind `ORG`/`POSITION`）；不复用 ReOrgTreePanel。
5. **左栏数据源门禁（§10 轨道 1）**：前端 `hasPerms(ORG:VIEW)` 探查，缺失时左栏 `el-result` 占位不发请求；岗位不前端探查（后端按调用者 ORG:VIEW_POSITION 裁剪岗位节点）。
6. **树配置边界**：不传 treeConfigId（默认树子树，契约字面）；多树租户其他树不在本入口可选范围（已知边界，登记设计 §9）。
7. **刷新自愈**：主体切换/入口 query 预选沿用 refreshAndPreset 既有管线（decideRefreshAction 对组织入口同样适用——preset/syncName/clearSubject 三分支类型无关）；未新增 subjectType watch（入口均经其他页跳转触发 onActivated，URL 直改为整页重载触发 onMounted；同路由程序化切换当前无调用方，避免过度设计）。
8. **saving 防重复提交**：继承 T-FE-018 grant-store isSaving 冻结（frozen 计算属性含主体切换禁点），本任务无改动。
