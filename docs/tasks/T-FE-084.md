## 背景

来源：原报告（外评快照按定规不入库） §四授权页、strict 与组件结构；覆盖定位见[范围映射](evidence/architecture-boundary-remediation/scope-map.md)。基线为 `44e5b03e2`，原报告的推测与测试声明不自动作为本任务已完成证据。

授权页面存在草稿/基线/预览/未知提交结果/父子授权的真实状态；strict:false 降低静态检查，但不证明当前已出现数据错误或需要全仓开 strict。

## 范围

走查关键状态转换和跨组件隐式协调，定位授权模型、会话与 API 边界的具体 any/可空风险和纯逻辑可提取点。

## 当前口径

当前仅纳入核查与方案定稿，未授权按推荐方向修改产品或代码。推荐先明确状态转换及局部类型，对有稳定职责的组件/纯逻辑模块做局部整理。备选保持结构补关键类型；不按行数拆文件，不全仓开 strict 后用断言消音。

待用户逐项确认：哪些用户行为或类型风险值得改、组件职责与兼容边界；任何未知提交结果语义变化先确认。 核查时须提供真实场景、数据/调用证据、现在未暴露的原因、推荐及备选方案的实际后果。

权威回写位置：[docs/design/frontend/permission-grant.md](../../docs/design/frontend/permission-grant.md)、[docs/design/frontend/login.md](../../docs/design/frontend/login.md)、[docs/design/project-rules.md](../../docs/design/project-rules.md)。本卡处于 proposed，仅编排后续工作；本次建卡不执行生产代码或测试改动。核查卡只授权形成证据/方案，具体实现必须由用户确认后另行登记实现卡。现有明确取舍按原范围消费，不重复要求用户决定。
