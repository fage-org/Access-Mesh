# T-FE-057 岗位停用后可发现与恢复

## 背景

承接[评审证据](../archive/2026-09-20/comprehensive-review.md)的 F007；基线与静态/动态证据强度见该记录。实施与验证见完成记录。

## 范围

- PositionTab管理列表状态筛选、状态显示和恢复编辑；区分管理列表与有效岗位候选。

## 当前口径

方案唯一入口：[IAM闭环方案](../design/iam-task-closure.md#position-lifecycle)（§4.1 已转已实施，2026-09-22）。

**启动拍板（2026-09-22，AskUserQuestion 三问，registry 同日行）**：①恢复入口=编辑弹窗改状态单选（与组织同 OrgForm 先例，不新增行内快捷开关）；②停用岗位上成员挂载/移除/授权/删除等写操作维持可用（后端事实链负责语义，界面不造本地规则）；③验收证据形态=浏览器实测（T-ORG-003 让渡先例不适用于纯前端 UI 卡）。

## 完成记录（2026-09-22）

### 实施

- `PositionTab.vue`：`loadPositions` 查询经新增 `utils/positionList.ts#buildPositionPageQuery` 构造——status 缺省不下发（管理面=全部状态，停用岗位保留可见）；新增状态筛选下拉（服务端参数，MemberTab 同款先例；词汇「禁用」沿组织域 OrgForm/组织信息卡先例）；卡片状态标识=仅停用项红色 `el-tag`（例外标注，ConditionPicker 停用标注先例）；`statusFilter` watcher 变更即重查（重置/清空经同 watcher）；空态文案区分「无匹配岗位（调整关键词或状态筛选）」vs「暂无岗位数据」；八处失败提示换绑 `toErrorMessage`（后端 body 文案优先，T-FE-051 同款——验收②「恢复失败有可行动提示」）；`loadPositions` 补请求代际守卫 `positionReqSeq`（双轨评审 P3-1 处置，用户拍板本卡顺手加——筛选/组织切换并发时旧响应不回写列表与 loading；组件无挂载测试设施，守卫以静态核对+四门为证）。
- 「分配用有效岗位候选排除停用」面（验收③）核实零改动：授权页主体树请求层 `getOrgTree({ includePositions: true, status: 1 })`（SubjectTreePanel.vue:111，2026-09-04 用户决策）；用户详情面板岗位只读（岗位由岗位 Tab 维护）；新增用户表单只选普通组织——全仓无其他岗位候选选择器（双轨代码轨类推扫描 `status: 1` 全仓 18 处逐点定性复核无同款管理列表残留）。
- 后端零改动（`/org/page` status 本就可选，三层契约链〔前端类型→OrgPageReq→mapper 动态条件〕经代码轨评审实证闭合；向停用岗位挂成员本就不拒绝——停用效果走事实链）。

### 验证

- **回归锁（红跑实证）**：`positionList.spec.ts` 4 用例——先以旧形态（固定 status:1）实现被测函数跑红（3 红：默认含 status 键/status:0 透传失败/orgId 键恒下发），修实现后 4/4 绿（代码轨独立推演复核 3 红 1 绿与声明一致）。
- **四道门**：vitest 35 文件 410 全绿（含新增 4 例）、typecheck、lint、build 全绿（评审处置后复跑仍全绿）。
- **浏览器实测（dev 栈，用户拍板证据形态）**：重建 dev 库（runbook 三步）+ bootstrap 种 admin + access-service/gateway（.env 密钥）/前端 8890 起栈；全链路：登录→组织与用户→岗位管理→新增岗位（启用）→列表可见无标签→**编辑禁用→列表保留+红色「禁用」标签**（旧实现此步岗位消失=F007 缺陷本体）→筛选「启用」=空+「无匹配岗位」文案→筛选「禁用」=岗位可见→编辑恢复启用→筛选「禁用」下消失（事实链生效）→重置=全部、无标签；截图入仓 `docs/tasks/evidence/t-fe-057/position-disabled-visible.png`（T-ACCESS-021 惯例）；冒烟数据（测试岗位）已删除清理。
