## 背景

定案④（registry 2026-09-19「前端会话/交互外评处置立项」行）：高影响操作确认 = **跨层级拖拽 + 角色禁用都加确认**。初判「仅禁用」，codex sol 复评证伪其依据「实例级角色授权当前无人用」（混淆数据状态与机制约束——授权页类型候选含 ROLE、GrantDialog 支持 INSTANCE 多选、update/move 实例级 MANAGE 闭包默认开）后用户改判。口径：仅 parentId 变化的拖拽（角色树+组织树 inner/跨父）加确认，同级排序直接生效；禁用确认文案含「全部持有者立即失去该角色权限」。

两棵树的父链镜像均后端代码级实证（本卡盘点）：`upsertRoleResource`（LocalProjectionDomainServiceImpl:369）按 parentRoleId 镜像角色树父链；`upsertAdminOrg`（同文件:186-224）把组织树父链镜像进 `abstract_role(ORG).parent_id` 与 `resource_entity(ORG).parent_resource_id`——拖拽改变层级即改变实例级管理覆盖与 remove 级联范围，确认文案引用该后果属实。

现状缺口：角色页 `handleToggleStatus` 无任何确认直接禁用；两棵树拖拽均直接调 move/update 无确认。

## 范围

- `views/system/role/utils/hook.ts`：`handleToggleStatus` 禁用确认 + `handleNodeDrop` parentId 变化确认（含原/新上级名解析，复用 `findNodeInTree`）。
- `components/ReOrgTreePanel/src/index.vue`：拖拽事件切 `node-drop` + 面板内确认；确认判定提取 `confirmOrgMoveIfNeeded` 可测模块（同目录 spec）。
- `views/system/role/utils/hook.spec.ts` 新建（role hook 首个 spec）。
- 设计回写 role-manage.md §4.1。

## 当前口径

- 确认落位：角色树/启停在 hook（hook 可 import 测试）；组织树在面板（本组件删除确认先例——确认在面板、执行在消费方，emit `node-move` 语义不变）；确认判定提取组件目录模块以获得回归锁（SFC 内函数不可 import，T-FE-050 提取先例）。
- 组织面板 `allow-drop` 限 `inner`：node-drop 真实落点必为 inner 且必是换父（拖入自身父节点为 dropType='none' 不触发）；确认判定仍保留 parentId 变化检查（防御未来 allow-drop 放宽）。
- role hook 既有 catch 直透 `error.message` 形态维持不动（T-FE-051 遗留登记，统一文案触达面另行收口——本卡不顺带避免半转换文件）。
- move API 不含 sortOrder：同父 before/after 服务端无实际排序变化（现状语义，非本卡面）。
