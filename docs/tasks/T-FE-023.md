# T-FE-023 扩展性验证 + 扩展指南

> 状态：done（2026-09-12 收口；指南 status: 待确认（评审稿）——用户确认后转 adopted）
> 原标题「SPI 策略扩展验证 + 扩展指南」；范围与验证形态已重定调（定案登记见 decision-registry 2026-09-12 两行）

## 当前口径（范围与定位）

立项时的三条验证线（SPI 策略扩展 + 配置驱动 + 代码级扩展指南）经盘点定性：

| 原设想 | 现状 |
|---|---|
| SPI 条件评估扩展 | **不存在**：条件操作符封闭 4 类（DATE_RANGE/TIME_RANGE/IP 白/黑名单），`ConditionEvalUtils` perm-common 静态实现，Gateway 与 access-service 共享，无扩展插槽 |
| SPI 权限源 | **概念已消亡**：统一引擎唯一事实源（role_perm_entry + 同事务投影，T-PERM-057） |
| 配置驱动 | **已成立且为产品主扩展面**：自有资源类型（类型级所有权 T-PERM-052 + 操作位按类型隔离 T-PERM-049）→ sync 通道 → 授权 → 判定；自有 subject_type/role_type 走 abstract-user/abstract-role 同步通道 |
| 代码级扩展指南 | 本任务产出；example-service 已演示接入形态；前端有固定页面扩展模式 |

两项范围定案（registry 2026-09-12 同日行）：

1. **指南定位 = 跨端全景**：落 `docs/design/extension-guide.md`（design 根，取代原 design_refs 的 `frontend/extension-guide.md` 纯前端口径）；受众=接入方/二开者（服务接入 + 自有类型扩展 + 条件边界 + 前端页面扩展一章）。
2. **验证形态 = 补自有资源类型端到端用例**：容器组 `CustomResourceTypeSlicePgIT`（声明→操作定义→服务身份同步→授权→引擎判定 + fail-closed 负向组）；另两场景（特殊判定逻辑边界、自有主体类型）文档级走查（指南 §4/§5/§6 承载）。

- 前端工程约束细节不在指南重复（指向 frontend/README 与前端 rules）。
