# T-FE-066 前端工程门禁进 CI

## 背景

前端质量门禁完全不在 CI：ci.yml 只有两个 Maven job；vitest（43 spec）、typecheck、lint 只在本地 pnpm 脚本与 husky pre-commit（CI 下短路）。前端 95 vue+196 ts 体量零 CI 覆盖——只改前端的 PR 破坏 spec/typecheck 直接进主干。http 工具层 RequestMethods 放行七种方法（项目规范禁 GET/PUT/DELETE，工具层不封口，新代码抄错先例类型系统不拦）。api 层头部注释两种网关口径并存（/perm 前缀旧叙述 vs 单命名空间新口径）+多处重复叙述已删除的 mock 史。

## 范围

CI 前端 job、http 类型封口、注释口径清扫。

## 当前口径

CI job 覆盖 lint+typecheck+vitest；类型封口取「RequestMethods 收紧+get() 具名导出退役」双管（现状具名导出为 post+get 两个，get 通道保留即留非 POST 逃生口）；注释清扫以现行单命名空间口径统一。

## 验收对照

- [ ] CI 前端 job 绿且覆盖三件
- [ ] RequestMethods 收紧+get() 退役+变更锁
- [ ] 注释口径统一（grep 旧口径残留为零）

## 非目标 / 遗留

- CI push 跑容器轨/E2E 的收口形态评估（归 T-ACCESS-089 维护者工程）。
