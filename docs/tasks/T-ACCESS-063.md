# T-ACCESS-063 decision-registry 双册分层与行文瘦身治理

## 背景

registry 2026-08-28 诞生，一个月长至 355KB/213 行（9 月 209 行，增速 ≈350KB/月）：主代理整读超工具上限（>256KB）、外评通道整读吃上下文（codex sol 无注入档约 258k 有效窗口，registry 一项占四成）。体积大头是收口/外评处置叙事整段写进定案行（平均 938 字符、33 行 >1500）——任务卡与 commit body 本已承载。纯时间窗归档无效（全部行龄 <30 天）。

2026-09-26 用户三项拍板：①存量=迁移性压缩+判据迁移（豁免「历史行不改写」一次性纪律，git 历史为全文备份）；②新行=定案口径硬上限 200 字+叙事外置；③结构=双册分层（现行册整读/历史册 append-only 只 rg）。

## 范围

- registry 头部协议修订（双册/判据/上限/消费协议）+ 存量迁移 + 本次治理定案行（≤200 字，示范新协议）。
- AGENTS.md 权威表行、三 skill 双副本同步。

## 非目标 / 遗留

- 不引入索引生成工具/漂移检查（仓库既有定规维持）；历史册不设体量上限（无人整读）。
- 已推翻 7 数据行（节合计 ~5.7KB）按「随龄 ≥60 天迁」判据目前全部未到期，本轮不动。

## 实现记录（2026-09-26）

**测量定性**：registry 355KB/224 个 `\| 2026-` 行（9 月 209 行、增速 ≈350KB/月），体积大头=收口/外评处置叙事整段入行（33 行 >1500 字符）；已推翻节仅 ~5.7KB。纯时间窗归档无效（全部行龄 <30 天）。

**执行**：

- **头部协议重写**：双册分层（现行册整读/历史册 append-only 只 rg）、归档判据（载体已全部归档或被现行文档吸收→原文迁历史册；常青行永留；已推翻 ≥60 天迁；载体路径须对活树重解析）、定案口径 ≤200 字硬上限+叙事外置、消费协议双册口径。
- **判据迁移**：载体活树重解析分类（63 归档/112 活/38 不可判），逐行裁定常青例外 33 行（Locale/BIGSERIAL/清空协议/分页方言/写锁机制/所有权/raw 严格化/var 允许等仍约束活代码的口径行永留）后，**30 行过程/评审/立项叙事行原文迁历史册**；38 行不可判（多为治理会话定规）全部保守留现行册。
- **迁移性压缩**：145 行 >400 字符分三批并行子代理压缩（41.8K→23.7K / 51.6K→22.8K / 63.9K→35.3K 字符，总量压至 ~52%），组装校验日期/四列结构/行数守恒，抽查 R2 与能力包融合行口径保真（①②③取舍结论与勿再报实质保留）。
- **顺带修复**：主表内 10 处空行断表（GFM 插行陷阱历史残留）随重建消除。
- **配套**：AGENTS.md 权威表行补现行册/历史册口径；external-review（模板第一步双册+构建标准）、dual-track-local-review（豁免段）、design-plan-task-lifecycle（登记路由）三 skill .claude/.agents 双副本同步+diff 验证。
- **治理定案行**已入现行册（≤200 字口径，示范新协议）。

**终态与守恒**：现行册 163KB/184 行（可整读，Read 工具 256KB 上限内）；历史册 58.5KB/30 行 append-only；已推翻节与 HEAD 逐字节等量（表头+分隔+7 数据行）；迁移+压缩前后定案行零丢失（脚本断言+日期逐行比对）。存量压缩按「口径保真优先」执行（原 1.5K+ 行压至 43-56%，未逐行硬卡 200 字）；200 字硬上限自新行起执行。
