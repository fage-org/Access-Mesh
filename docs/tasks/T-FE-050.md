> 状态：done（2026-09-19 收口）

## 背景

2026-09-19 外评处置立项时发现：`user/index.vue` 的 `findParentOrgName` 把「未找到」哨兵 `"未知"`（truthy 字符串）混入递归返回值——`const found = findParentOrgName(node.children, parentId); if (found) return found;` 在第一个子树查找失败时拿到 `"未知"` 即真值返回，**后续兄弟子树永不遍历**。codex sol 外评核实该 bug 仅在 user/index.vue（PositionTab 同名函数系返回 null 的正确实现，非同款 bug——主代理误报已撤回，见 registry 2026-09-19 立项行）。

数据示例：树根为 [研发部(id=1, 含前端组 11/后端组 12), 市场部(id=2, 含品牌组 21)]，选中品牌组查 parentOrgId=2 → 先钻研发部子树 → 递归返回「未知」(truthy) → 整体返回「未知」，市场部永不被遍历。信息卡显示「上级部门：未知」（应为「市场部」）；openOrgForm 编辑态父组织名同源同错。

## 范围

- `user/index.vue`：删除内联 `findParentOrgName`（含错误实现），改 import `./utils/orgTree`；两处调用点包 `?? "未知"`。
- 新建 `user/utils/orgTree.ts`：导出修复后的纯查找函数（`string | null`）。
- 新建 `user/utils/orgTree.spec.ts`：回归锁。

## 边界（与 Q-017 / T-FE-051 分工）

- **Q-017（index.vue 死解构 + 点组织双请求）2026-09-19 用户拍板留给 T-FE-051**：本卡不顺带收敛——Q-017 两个设想方向（selectedOrgId 就地化 vs 状态上提共享单实例）正是 T-FE-051「composable 化」的设计决策面，051 反正要动同文件同批行（定案见 decision-registry 同日行）。
- PositionTab 自有 `findParentOrgName`（正确实现）不动——不做跨文件去重合并（051/后续按需评估）。
- `findOrgById`（index.vue 内，正确实现）不提取、不动——最小修复面。

## 当前口径

纯查找函数不掺展示文案：null=未找到，「根组织」「未知」等文案由调用点决定——与 PositionTab 实现形态一致（计划口径「PositionTab 系正确实现」即对齐目标）。

## 非目标 / 遗留

- 空字符串组织名（`if (found)` 会跳过 falsy 名）——与 PositionTab 同款边缘；新旧实现对空名行为等价（都跳过继续遍历，最终显示「未知」），不另设防御。
- Q-017 收敛、loadTable 接线、handleToggleStatus catch 透 message——均归 T-FE-051。
