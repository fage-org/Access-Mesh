# 专属资源归属与通用资源引用

<a id="scope"></a>
## 1. 目标、状态与适用范围

2026-10-21 用户确认资源关系方向并授权逐项实施：专属类型的实例唯一归属于主资源，实例及归属由业务系统管理；通用类型的实例由权限管理系统管理，业务系统按类型整体引用，不选择引用其中部分实例。整类引用只决定可用目录，管理员仍可给用户授予其中部分实例。操作定义按资源类型共享，现有授权入口增加候选过滤，不增加独立入口。

通用整类引用取代本文件原先的通用实例级引用目标；不再采用同一通用类型中“A 引用 X/Y、B 只引用 X”的关系模型或验收场景。专属实例归属与用户实例级授权保持。

本文件为**已采纳目标，部分实现，整体尚未交付**。T-ACCESS-145 已定稿，T-ACCESS-146 已实现关系存储、类型声明、原子发布及写生命周期基础，T-ACCESS-147 已实现候选/只读查询和 SDK；授权与运行时、页面和 example 接入仍按计划推进。实施契约见[契约总册目标章节](access-service-api-contract.md#resource-association-contract)，执行与验证由 [resource-association-plan](../plans/resource-association-plan.md) 编排；不能以候选过滤代替完整鉴权能力已交付。

适用对象是显式声明此能力的资源类型。未声明的现有类型保持现役行为，不默认把所有类型归为通用并强制补关系。2026-10-21 用户确认：关系模式及允许主类型声明只能在没有有效实例、关系和用户业务授权时修改，系统自动生成的 AUTHORITY_ROOT 不算用户业务授权；已有使用时不得直接转换用途。名称等不改变关系语义的普通资料仍可编辑。需要改变用途时另建类型并准备资源，本计划不做保留旧数据的在线转换，不能用新规则隐式扩围既有业务。

不建设资源内自定义操作、每主资源独立类型、通用关系图、递归归属、独立配置页、授权模板传播、行列配对规则或金额更新接口。不改报表定义编辑 UPDATE 与数据编辑 DATA_EDIT 的区分，不恢复已取消的 BI 前端。不因本计划引入历史数据迁移或双写系统；适用现行空库重建约束。

## 3. 对象、关系与操作复用

| 类型性质 | 实例身份 | 与主资源的关系 | 操作定义 |
|---|---|---|---|
| 专属 | A.amount 和 B.amount 是两个不可复用的技术身份，即使显示名相同 | 每个实例必须唯一归属于一个主资源 | 同类型共享 DATA_READ / DATA_EDIT 等定义 |
| 通用 | X 市只登记一个稳定实例 | A、B 引用整个通用类型；该类型的有效实例都属于候选，不逐个维护实例引用 | 同类型共享定义 |
| 未声明本能力 | 现有身份规则 | 现有语义 | 现有语义 |

共同约束：同租户；按业务键定位、服务端解析内部身份；不从名称、路径或手工拼串反解。关系允许的主资源类型由已定稿的类型声明约束；进入子权限候选或保存授权时还须满足现行 SUB_PERM 策略，不能把目录关系与授权许可混为一项。关系仅一层，首期不引入关联资源再作为关系主资源的递归组合。资源树若保留，必须明确祖先/后代展开不得跨越专属归属或通用引用边界。

归属/引用与 parent_id（树继承）、depend_on（授权依附）、owner_service_code（维护来源）分别建模。业务系统管理实例不自动取得类型/操作定义的任意修改权；类型及操作仍按可信注册和现有管理门禁登记。共享定义修改影响该类型全部实例，不能按单报表解释。

存储须区分两种目标身份：专属关系指向具体资源实例，通用引用指向资源类型定义。通用整类引用不得展开成可分别编辑的逐实例关系，也不得为尚未新增的实例预建关系。只保留实际业务关系，不抽象任意关系种类、图遍历或策略插件。是否共表及最终字段、唯一性、软删除形状在 [schema 唯一权威](schema/access-service.sql) 定稿。专属唯一归属不得仅凭应用层先查后写；禁止声称普通 CHECK 可以跨表读取类型模式来保证基数。

<a id="ownership"></a>
## 4. 维护职责与信任边界

| 对象 | 实例维护 | 关系维护 | 角色授权 |
|---|---|---|---|
| 专属字段等 | 指定业务服务，复用 SYNC 来源约束 | 同一合法业务维护链路 | IAM 管理员按既有授权门禁 |
| 通用地区等 | IAM 管理入口，复用 MANAGED | 对主资源有合法维护资格的业务服务，维护整类引用 | IAM 管理员按既有授权门禁，可只选部分实例 |

关联入口只改变关系，不能借引用请求创建、改名、停用或删除 MANAGED 实例。租户、调用服务从可信上下文取得，不能信任请求自报来源。维护 A 的服务不能修改其他服务维护的 B 的引用；专属目标实例与通用目标类型须在同租户、允许类型和有效目录内。类型声明不能任意拼出与上述职责相冲突的维护组合。

管理面可显示关系和维护来源；业务维护的关系在 IAM 中只读。通用实例可在现有资源管理页维护。是否需要补类型声明表单及只读引用展示，由原类型/资源页面承载，不新建关系管理产品。

<a id="publication"></a>
## 5. 同步、事务与身份生命周期接线

专属实例与归属应在同一 IAM 事务内建立，不能先发布无归属字段再依靠人工补齐。主资源不存在时，按定稿的依赖缺失协议处理；不建虚假主资源。业务数据库与 IAM 不构成分布式原子事务，复用现有可靠发布与重试，不在本地数据库事务中调用远端。

通用类型及实例由 IAM 管理，业务系统引用类型业务键并维护自身按实例业务键定位的业务谓词映射；业务侧映射不成为通用实例第二个可编辑权威源。整类引用不接受实例子集；类型下新增有效实例属于其候选目录，但不会仅因成为候选就自动产生用户实例授权。INSTANCE 返回项缺少业务映射时沿现有配置错误拒绝，ALL 保持既有全范围含义，详见 [example 发布接线](example-service-api-contract.md#resource-association-publication)。关系发布复用现有资源 sync/full-sync 的同步版本、身份、审计和失败分类，不新增平行发布基础设施。全量清理只能覆盖调用服务有权维护的主资源及其关系，不得删除通用实例或他方关系。

写入口清单必须包括管理/同步 single 与 FULL、资源树移动、类型与资源删除、服务与租户生命周期、bootstrap/种子、授权计划、自动依赖物化，以及引入的关系入口。按实际触达职责逐项登记适用或不适用及理由，不把管理入口只读当作覆盖其他写者的证明。

并发遵循[工程规范](project-rules.md#backend-concurrency)与[公共锁规范](redis-transaction-locks.md#transaction-lock-contract)：枚举专属双重绑定、关联与主/子删除、关系解除与授权提交、类型模式修改、FULL 与增量竞争；锁内读取最新事实，数据库约束共同保证一致性。复用现有领域锁门面，确需 Redis 互斥才使用公共组件，不另建锁框架。授权授撤、审计与提交后失效按[文档治理写入口清单](project-rules.md#decision-governance)登记。

<a id="authorization"></a>
## 6. 配置、保存与运行时边界

候选集合先满足现行 SUB_PERM 策略及对象有效性，再按模式限定：专属类型只取归属于当前主资源的实例；通用类型在主资源已有效引用该类型时提供整个类型的有效实例，未引用则不提供该类型候选。用户仍可只获其中部分实例授权，候选不等于授权。未声明本能力的类型继续现行规则。无关系、无候选、无权限和读取故障分别表达，故障不回退全部资源。

保存端复用 apply-grant-plan，并在同一写入边界校验归属/引用；A 主授权挂 B 专属字段、A 未引用某通用类型却挂该类型实例均拒绝。A 已引用该通用类型时，可以只授其中某个地区。删除关系与提交授权的竞争不能留下可生效的悬挂配置。主授权、目标角色、子类型和来源只读等既有规则继续生效。

“共用地区实例”不等于“共用子授权”：A 主授权下授 X 市，不使 B 主授权下自动得到 X 市。关系建立本身不新建角色授权，但已有 DIRECT / 类型级 ALL 可能在新关系上下文产生贡献，不能承诺关联变化完全没有授权影响。

运行时必须消费关系及主/关联资源状态。关系过滤进入共享查询流程及同源范围投影，不能只在页面隐藏。保留 QueryGate / QueryExecutionEngine 为判定入口，不新增独立判定算法、不逐字段递归 execute、不在多个业务接口复制关联校验。过滤、四态及错误规则见[契约总册目标章节](access-service-api-contract.md#resource-association-contract)，父来源规则见[引擎设计](engine/implementation.md#association-parent-sources)。

必须覆盖 query-scopes、带父上下文 check/batchCheck、DIRECT、DEPENDENT、资源树继承、转授检查与准入/快照的适用边界。无主上下文的直接检查不能虚构当前报表，准入不代替最终判定；普通类型和无关联语义的查询不增加无关扫描。

**ALL 与实例选择（2026-10-21 用户确认，目标待实施）**：通用类型在被当前主资源有效整类引用后，ALL 保持既有全范围含义；example 中仍表示整份数据集，不改为有效目录实例所表达范围的并集。删除或停用某实例只移除该实例授权来源的贡献，不撤销独立 ALL，也不将其对应业务数据改成 ALL 不可访问。DIRECT 与 DEPENDENT 均先满足关系适用性，再按现役授权规则贡献；解绑整个类型时 ALL 也不能在该主资源中贡献。

专属字段 ALL 只覆盖当前主资源已登记且有效的专属实例，不能跨归属；新增有效字段可被既有显式 ALL 覆盖。界面“选择当前全部”保存具体实例集合，以后新增实例不自动加入这组固定授权，不新增独立 owner-ALL 授权模式。类型级授权根和无主上下文的转授资格仍保留其原用途；运行时有主上下文时消费归属/引用边界，不能以维护授权根为由绕过关系。

**父授权来源完整收集（2026-10-21 用户确认，T-ACCESS-148 实施中）**：需要计算子权限时，所有满足父上下文、条件及互斥规则的主授权都进入绑定来源集；父类型 ALL 命中不得跳过具体主资源授权及其子项。范围查询与带父上下文的 check/batchCheck 使用同源规则；普通不计算子权限的布尔检查保持既有短路。该范围内取代现行 P05 不扩读父实例边界，不能据此改写无父上下文查询或自动绕过条件与互斥。实施位置见[引擎设计](engine/implementation.md#association-parent-sources)。

关系变化的撤权时效须覆盖角色事实、资源状态及受影响准入快照。复用[缓存框架](../../.agents/skills/dual-layer-cache-framework/SKILL.md)和既有预算，不新增全局权限版本、不承诺跨服务即时撤权。首期新关系读取优先批量数据库查询；有实际性能证据再决定新增缓存，不先造专用缓存体系。

## 7. 删除、停用与重新引用

| 事件 | 目标行为 / 定稿要求 |
|---|---|
| 撤销某角色主授权 | 现有子授权回收；不删除资源及关系 |
| 删除主资源 A | 专属资源及其授权按一致性边界回收；通用资源仅解除 A 引用，不误删 B 引用或实例 |
| 专属资源改名 | 身份不变；改归属不是普通文案更新，首期不提供任意迁移归属 |
| 同名删除重建 | 新身份，不复活旧授权；业务编码可复用，参与关系的业务资源来源身份不可复用；归属请求核验预期主来源身份，旧字段迟到事件不得挂到同码新主资源 |
| 通用实例删除 | 允许 IAM 管理员按现有删除门禁删除，即使其类型仍被引用；清理该实例相关授权，整类引用及其他实例保持，所有使用方停止使用被删实例；同名重建是新身份 |
| 通用实例停用 | 该实例授权在所有引用方退出有效贡献，授权记录保留；独立类型 ALL 不因此撤销或缩窄。恢复不自动修改各主资源自身状态 |
| 被引用通用类型删除 | 即使类型内已无实例，只要仍有有效整类引用就拒绝删除；先由业务服务解除引用，再按既有类型删除条件处理 |
| 解除并重建通用类型引用 | 删除明确依附当前主资源实例主授权、属于被解绑通用类型的子授权；父 ALL 下共享子授权及 DIRECT/类型 ALL 保留。解绑期间该类型不能在当前主资源上下文贡献；重绑不恢复已删除子授权，保留来源可按当前条件重新贡献 |

**解绑清理规则（2026-10-21 用户确认，T-ACCESS-148 实施中）**：解除通用类型引用时，按当前主资源实例主授权的真实身份，跨角色清理属于该通用类型的子授权，包括其具体实例和类型 ALL 子行；不删除其他类型子项、其他主资源下的子项、父 ALL 下可共享的子项或 DIRECT/类型 ALL 主授权。解绑期间保留来源也不能在该主资源上下文贡献，重新引用后它们可按当前资源身份、启停状态、条件与互斥重新贡献；被清理的子授权须重新授予。此规则取代解绑时保留全部授权的方案，不能承诺重绑后绝无权限恢复。解绑 A 不影响 B 的引用和共享来源。资源删除另按身份生命周期处理，同名重建不能接续旧关系和旧实例授权。

<a id="ui"></a>
## 8. 现有页面调整

保留角色授权页及其子权限配置器，不新增独立入口。焦点主授权提供主资源上下文，子类型选择继续按 SUB_PERM；专属对象目录按归属过滤，通用类型候选按整类引用过滤，其实例可单独勾选授权，不展示逐实例引用开关。切换 A/B 时取消过期加载、隔离勾选与草稿；同名字段显示所属主资源及必要编码，不能仅按显示名匹配。

类型页显示或配置已定稿的关系性质及来源声明；资源页沿 MANAGED/SYNC 展示可编辑性、关联数量/引用与来源，业务维护关系只读。这些是原页面接线，不引入关系编辑工作台。

缺关系、未发布、无允许子类型、加载失败分别提示；历史/异常授权可诊断与清理，不静默隐藏。条件、依附来源、ALL 的真实范围保留可见。原联合授权保存及后端门禁复用，新增响应字段同步 DTO 对账清单。新类型的未知模式必须拒绝或明确不可配置，不能被旧客户端误当作普通无限制类型。

<a id="example"></a>
## 9. example 接入与联合场景

复用现有报表、字段和行范围解释器，不新建 BI 页面，不开放金额普通更新端点。A.amount/B.amount 用读权限验证独立身份；已有 remark 写端点验证 DATA_EDIT 与行列约束，避免用未实现的金额更新作为验收前提。

专属字段由 example 维护并发布归属；通用地区实例改由 IAM 管理链路准备，example 只保留业务谓词映射和关联发布。现有 demo-scope/save、发布队列和准备脚本不得继续反向修改 MANAGED 实例；各自的保留/裁剪点须在 example 契约中明确。不为通用资源新增双向实例同步。

联合夹具：两张报表 A/B 有同名金额，均引用同一通用地区类型；X/Y 作为该类型实例同时成为两张报表的候选。普通角色不持默认全量授权，在 A 下只授 X、B 下只授 Y，验证共享目录不共享父授权贡献。另验证未引用该通用类型时不能配置其任何实例、A 字段不串 B、解除整类引用/实例停用后访问变化、删除 A 不损坏 B，再以单独的 DIRECT/ALL 身份验证定稿的广泛授权边界。浏览器验证现有配置入口，API/脚本和 SQL 证明真实执行；不以截图替代后端拒绝证据。
