# 专属资源归属与通用资源引用

<a id="scope"></a>
## 1. 目标、状态与适用范围

2026-10-21 用户确认资源关系方向，并要求据此制定计划与任务：专属类型的实例唯一归属于主资源，实例及归属由业务系统管理；通用类型的实例由权限管理系统管理，可被多个主资源引用，引用由业务系统管理。操作定义按资源类型共享，现有授权入口增加候选过滤，不增加独立入口。

本文件为**已采纳目标，尚未实施**。当前 API、DDL 和运行时仍以现役契约及代码为准；本文件不证明新能力已交付。具体实施契约须由 [T-ACCESS-145](../tasks/T-ACCESS-145.md) 按[定稿门槛](#contract-gate)闭合；下文标为“建议”的结构和行为不自动升格为用户定案。实施计划为 [resource-association-plan](../plans/resource-association-plan.md)。

适用对象是显式声明此能力的资源类型。未声明的现有类型保持现役行为，不默认把所有类型归为通用并强制补关系。类型启用、模式变更及空库初始化的限制在实施契约中登记，不能用新规则隐式扩围既有业务。

不建设资源内自定义操作、每主资源独立类型、通用关系图、递归归属、独立配置页、授权模板传播、行列配对规则或金额更新接口。不改报表定义编辑 UPDATE 与数据编辑 DATA_EDIT 的区分，不恢复已取消的 BI 前端。不因本计划引入历史数据迁移或双写系统；适用现行空库重建约束。

## 3. 对象、关系与操作复用

| 类型性质 | 实例身份 | 与主资源的关系 | 操作定义 |
|---|---|---|---|
| 专属 | A.amount 和 B.amount 是两个不可复用的技术身份，即使显示名相同 | 每个实例必须唯一归属于一个主资源 | 同类型共享 DATA_READ / DATA_EDIT 等定义 |
| 通用 | X 市只登记一个稳定实例 | 可被 A、B 引用；尚未被引用的实例可存在于公共目录 | 同类型共享定义 |
| 未声明本能力 | 现有身份规则 | 现有语义 | 现有语义 |

共同约束：同租户；按业务键定位、服务端解析内部身份；不从名称、路径或手工拼串反解。关系允许的主资源类型由已定稿的类型声明约束；进入子权限候选或保存授权时还须满足现行 SUB_PERM 策略，不能把目录关系与授权许可混为一项。关系仅一层，首期不引入关联资源再作为关系主资源的递归组合。资源树若保留，必须明确祖先/后代展开不得跨越专属归属或通用引用边界。

归属/引用与 parent_id（树继承）、depend_on（授权依附）、owner_service_code（维护来源）分别建模。业务系统管理实例不自动取得类型/操作定义的任意修改权；类型及操作仍按可信注册和现有管理门禁登记。共享定义修改影响该类型全部实例，不能按单报表解释。

建议使用统一的主资源—关联资源关系存储：专属模式为主资源对专属实例的一对多（每个专属实例只有一个主资源），通用模式为多对多。只保留这一实际业务关系，不抽象任意关系种类、图遍历或策略插件。最终字段、唯一性及软删除形状在 [schema 唯一权威](schema/access-service.sql) 定稿。专属唯一归属不得仅凭应用层先查后写；禁止声称普通 CHECK 可以跨表读取类型模式来保证基数。

<a id="ownership"></a>
## 4. 维护职责与信任边界

| 对象 | 实例维护 | 关系维护 | 角色授权 |
|---|---|---|---|
| 专属字段等 | 指定业务服务，复用 SYNC 来源约束 | 同一合法业务维护链路 | IAM 管理员按既有授权门禁 |
| 通用地区等 | IAM 管理入口，复用 MANAGED | 对主资源有合法维护资格的业务服务 | IAM 管理员按既有授权门禁 |

关联入口只改变关系，不能借引用请求创建、改名、停用或删除 MANAGED 实例。租户、调用服务从可信上下文取得，不能信任请求自报来源。维护 A 的服务不能修改其他服务维护的 B 的引用；目标资源须在同租户、允许类型和有效目录内。类型声明不能任意拼出与上述职责相冲突的维护组合。

管理面可显示关系和维护来源；业务维护的关系在 IAM 中只读。通用实例可在现有资源管理页维护。是否需要补类型声明表单及只读引用展示，由原类型/资源页面承载，不新建关系管理产品。

<a id="publication"></a>
## 5. 同步、事务与身份生命周期接线

专属实例与归属应在同一 IAM 事务内建立，不能先发布无归属字段再依靠人工补齐。主资源不存在时，按定稿的依赖缺失协议处理；不建虚假主资源。业务数据库与 IAM 不构成分布式原子事务，复用现有可靠发布与重试，不在本地数据库事务中调用远端。

通用实例先由 IAM 建立，业务系统引用稳定业务键并维护自身的业务谓词映射；业务侧映射不成为通用实例第二个可编辑权威源。关系发布复用既有同步版本、身份和审计能力中适用的部分，明确增量、重复请求、乱序、全量缺失清理及失败分类，不机械复制另一套发布基础设施。全量清理只能覆盖调用服务有权维护的主资源及其关系，不得删除通用实例或他方关系。

写入口清单必须包括管理/同步 single 与 FULL、资源树移动、类型与资源删除、服务与租户生命周期、bootstrap/种子、授权计划、自动依赖物化，以及引入的关系入口。按实际触达职责逐项登记适用或不适用及理由，不把管理入口只读当作覆盖其他写者的证明。

并发遵循[工程规范](project-rules.md#backend-concurrency)与[公共锁规范](redis-transaction-locks.md#transaction-lock-contract)：枚举专属双重绑定、关联与主/子删除、关系解除与授权提交、类型模式修改、FULL 与增量竞争；锁内读取最新事实，数据库约束共同保证一致性。复用现有领域锁门面，确需 Redis 互斥才使用公共组件，不另建锁框架。授权授撤、审计与提交后失效按[文档治理写入口清单](project-rules.md#decision-governance)登记。

## 6. 配置、保存与运行时边界

候选集合 = 现行允许子类型内的有效对象 ∩ 当前主资源的有效归属/引用对象；未声明本能力的类型继续现行规则。无关系、无候选、无权限和读取故障分别表达，故障不回退全部资源。

保存端复用 apply-grant-plan，并在同一写入边界校验归属/引用；A 主授权挂 B 专属字段、A 未引用的地区均拒绝。删除关系与提交授权的竞争不能留下可生效的悬挂配置。主授权、目标角色、子类型和来源只读等既有规则继续生效。

“共用地区实例”不等于“共用子授权”：A 主授权下授 X 市，不使 B 主授权下自动得到 X 市。关系建立本身不新建角色授权，但已有 DIRECT / 类型级 ALL 可能在新关系上下文产生贡献，不能承诺关联变化完全没有授权影响。

运行时必须消费关系及主/关联资源状态。关系过滤进入共享查询流程或其确定的同源消费边界，不能只在页面隐藏。保留 QueryGate / QueryExecutionEngine 为判定入口，不新增独立判定算法、不逐字段递归 execute、不在多个业务接口复制关联校验。最终过滤位置、四态输出、事实解释与配置错误协议由 T-ACCESS-145 写回[引擎设计](engine/implementation.md#permission-query)和契约总册。

必须覆盖 query-scopes、带父上下文 check/batchCheck、DIRECT、DEPENDENT、资源树继承、转授检查与准入/快照的适用边界。无主上下文的直接检查不能虚构当前报表，准入不代替最终判定；普通类型和无关联语义的查询不增加无关扫描。

当前类型级 ALL 不能静默解释成“当前报表所有关联对象”。“选择当前全部”可保存明确对象集合；动态范围、父 ALL、授权根/种子及返回 ALL 后如何按关系消费，须先经过[定稿门槛](#contract-gate)，不直接切断现有广泛授权或默认为已提供 owner-ALL。父 ALL 短路可能遗漏实例父下子项的现行 P05 边界也须明确本计划是保留还是局部调整；不得默改所有布尔鉴权。

关系变化的撤权时效须覆盖角色事实、资源状态及受影响准入快照。复用[缓存框架](../../.agents/skills/dual-layer-cache-framework/SKILL.md)和既有预算，不新增全局权限版本、不承诺跨服务即时撤权。首期新关系读取优先批量数据库查询；有实际性能证据再决定新增缓存，不先造专用缓存体系。

## 7. 删除、停用与重新引用

| 事件 | 目标行为 / 定稿要求 |
|---|---|
| 撤销某角色主授权 | 现有子授权回收；不删除资源及关系 |
| 删除主资源 A | 专属资源及其授权按一致性边界回收；通用资源仅解除 A 引用，不误删 B 引用或实例 |
| 专属资源改名 | 身份不变；改归属不是普通文案更新，首期不提供任意迁移归属 |
| 同名删除重建 | 新身份，不复活旧授权；主资源同名重建也不能接收旧关系 |
| 通用实例删除 | 建议被引用时拒绝，显示引用范围；与并发新增引用共同守卫 |
| 通用实例停用 | 所有引用方退出有效使用；恢复不自动修改各主资源自身状态 |
| 解除并重建引用 | 解绑后旧关系不能继续贡献；精确实例子授权、父 ALL 下子授权、DIRECT/类型 ALL 的清理与重启用区别按 G2 定稿 |

“重新关联不恢复任何权限”不能作为未经限定的承诺：例如 DIRECT 广泛授权未撤销时，重新引用后可能重新产生贡献；父 ALL 下同一子行可能同时服务 A/B，不能为解绑 A 粗暴删除 B 仍依赖的行。此差异属于实施前业务语义，不由技术实现自行猜测。

## 8. 现有页面调整

保留角色授权页及其子权限配置器，不新增独立入口。焦点主授权提供主资源上下文，子类型选择继续按 SUB_PERM；类型候选与对象目录按关系过滤。切换 A/B 时取消过期加载、隔离勾选与草稿；同名字段显示所属主资源及必要编码，不能仅按显示名匹配。

类型页显示或配置已定稿的关系性质及来源声明；资源页沿 MANAGED/SYNC 展示可编辑性、关联数量/引用与来源，业务维护关系只读。这些是原页面接线，不引入关系编辑工作台。

缺关系、未发布、无允许子类型、加载失败分别提示；历史/异常授权可诊断与清理，不静默隐藏。条件、依附来源、ALL 的真实范围保留可见。原联合授权保存及后端门禁复用，新增响应字段同步 DTO 对账清单。新类型的未知模式必须拒绝或明确不可配置，不能被旧客户端误当作普通无限制类型。

## 9. example 接入与联合场景

复用现有报表、字段和行范围解释器，不新建 BI 页面，不开放金额普通更新端点。A.amount/B.amount 用读权限验证独立身份；已有 remark 写端点验证 DATA_EDIT 与行列约束，避免用未实现的金额更新作为验收前提。

专属字段由 example 维护并发布归属；通用地区实例改由 IAM 管理链路准备，example 只保留业务谓词映射和关联发布。现有 demo-scope/save、发布队列和准备脚本不得继续反向修改 MANAGED 实例；各自的保留/裁剪点须在 example 契约中明确。不为通用资源新增双向实例同步。

联合夹具：两张报表 A/B 有同名金额；共享地区 X 同时被 A/B 引用，Y 只被 A 引用；普通角色不持默认全量授权。依次验证 A 字段不串 B、X 目录复用但父授权贡献独立、B 不能选 Y、解绑/停用后访问变化、删除 A 不损坏 B，再以单独的 DIRECT/ALL 身份验证定稿的广泛授权边界。浏览器验证现有配置入口，API/脚本和 SQL 证明真实执行；不以截图替代后端拒绝证据。

<a id="contract-gate"></a>
## 10. 实施契约定稿门槛

需求和职责已确认；以下尚未闭合的实施语义由 T-ACCESS-145 先完成。技术细化可依据规范直接落地，影响用户可用权限的取舍须按决策提问协议举例确认。未消解的条目阻断下游，不被记录成用户已接受的风险；本计划已承接这些事项，不重复登记 pending-problems。

| 编号 | 必须回答的场景 | 交付依据 |
|---|---|---|
| G1 范围与来源 | A/B 共享 X，用户持 DIRECT 或类型 ALL；父 ALL 与实例父子项并存；类型授权根不可误禁。关联过滤后如何表示范围、是否动态包含新增对象、父来源如何完整或保持现行边界？ | 准确请求/响应、INSTANCE/ALL/EMPTY/DENIED 语义、来源与消费者矩阵；建议首期只在配置面提供当前对象显式全选，不新增动态 owner-ALL |
| G2 解绑与复用 | 解绑 A-X 后再绑定；X 的同一父 ALL 子授权仍服务 B；DIRECT 未撤销。哪些记录删除、哪些保留但过滤、哪些可以随新关系重新生效？ | 生命周期状态表及可重复反例；不能只写“不恢复旧权限” |
| G3 身份与发布 | 业务服务只维护 A，却提交 B 的引用；重复/乱序同步；主资源晚于字段到达；FULL 清理范围；类型已有实例后改模式；树继承跨关系 | 类型声明、服务资格、数据库约束/锁序、版本和清理协议、错误码、批量与响应大小上限 |
| G4 实施接线 | 查询/授权/自动依赖/准入/资源与类型删除/服务与租户清理；example 当前共享范围为 SYNC；SDK/前端新增字段 | 入口适用清单、DTO/SDK/DDL/种子回写点、查询新鲜度及原有能力回归矩阵 |

接口详细字段和错误码归[契约总册](access-service-api-contract.md)，可执行表结构归[唯一 DDL](schema/access-service.sql)，查询语义归[引擎实现](engine/implementation.md#permission-query)，页面行为归[授权页设计](frontend/permission-grant.md)，业务发布与 SQL 映射归[example 设计](example-permission-demo.md)。本文件不复制另一份正式 API 或 DDL。

## 11. 验收与减法边界

| 行为证据 | 首选验证层 |
|---|---|
| 类型模式、身份键、归属/引用候选及作用域计划 | 现有单元测试/纯逻辑测试补足变体 |
| 专属唯一性、跨租户拒绝、删除与绑定竞争、回滚、重复引用 | 复用 ItInfra 的真实 PostgreSQL 测试；禁裸 sleep |
| 旧入口切换 A/B、迟到响应、共享目录、只读来源、保存失败、DTO 字段 | 现有 Vitest 与必要的浏览器真实操作 |
| 同服务范围结果、DIRECT/ALL/父来源、树展开与解绑 | 引擎及领域定向测试，必要 PG 证据 |
