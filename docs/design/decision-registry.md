# 定案登记表（Decision Registry）——现行册

> 全仓定案的**唯一消费入口**：本表只存指针——日期 + 一句话口径 + 出处锚点 + 评审处置，定案正文仍在任务卡/设计文档，不在本表复制（模式同文档治理「入口引用不重复正文」）。会话内拍板、无仓库正文载体的定案，以本表为正文登记点（口径写全）。
>
> **双册分层（T-ACCESS-063，2026-09-26 拍板）**：本文件=**现行册**（整读消费面，保持可整读体量）；[decision-registry-history.md](decision-registry-history.md)=**历史册**（append-only，只 rg 不整读）。初稿 2026-09-06（初始收编既有散点）；此后用户定案当轮追加，不跨轮补记。

## 写入协议

- 用户每次定案（含 AskUserQuestion 结论、会话内拍板）**当轮登记**新行，按日期顺序追加。
- **行文硬上限（2026-09-26 拍板；同日钉单位）**：定案口径列 ≤200 字（**按汉字计数**——ASCII 标识符/哈希/数字不计，claude 外评 P3 处置拍板）；处置过程、评审逐项明细、拍板叙事不进本表（任务卡与 commit body 承载）；超长拍板拆多行各表一条口径。登记超限自行整改，评审按 P3 报超长行。
- 口径被新定案推翻：旧条目移入「已推翻」节并标注取代它的定案，**不删除**。
- **归档判据（计划归档批次时顺手执行，非定时）**：行满足「载体已全部归档（任务卡/计划已迁 `docs/archive/**`）或内容已被现行设计文档吸收」→ **原文不改写**迁历史册；**常青行永留**（评审处置「再报直接撤回」且仍约束活代码的口径类——退役禁令/UTC/线格式/缓存边界/分层规则等）；已推翻行龄 ≥60 天迁历史册。行内载体路径为登记时点快照，判定前须对活树重解析（归档后旧路径失效是常态）。
- 评审处置两档：
  - **再报直接撤回**：评审再报该口径即整条撤回，不进存疑队列、不占用用户决策时间；
  - **报了先核出处**：评审报相关问题时先对照出处锚点核实再定性。

## 消费协议

- 评审提示词豁免段：双轨子代理**整段注入现行册内容**；外评三通道（2026-09-12 v2 起）不注入——模板「硬性纪律」首步指令评审自读**现行册全文** + 槽位只挑任务相关行 + 报告首行声明已读。
- **历史册兜底（T-ACCESS-063）**：结论与现行册无命中但疑似既有定案时，先 `rg <关键词> docs/design/decision-registry-history.md` 再定性；历史册不整读。
- 评审结论先对照本表：命中「再报直接撤回」即撤回；命中「报了先核出处」先核出处锚点再定性。
- 验收口径：连续两个任务的评审中，已登记定案零进入存疑队列。
