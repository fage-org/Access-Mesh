# example-service 持久化权限演示

<a id="scope"></a>
## 1. 定位与确认范围

example 是拥有真实业务数据的权限接入样板，交付目标是可重复验证权限系统行为。业务外壳采用“报表资源 + 销售记录 + 自定义定时任务”，不建设数据分析产品。

2026-10-18 用户确认：CSV 数据入口；本人、团队、部门场景同时覆盖；数据权限必须动态配置，不能硬编码业务维度；导入报表的字段作为基于特定报表资源的数据权限；去掉数据分析和业务页面；example 使用内部调度，暂不接 access-service 现有任务管理。2026-10-19 已获授权逐步执行计划，[T-ACCESS-136](../archive/2026-10-20/tasks/T-ACCESS-136.md)已完成实施契约定稿；以下为现役实施边界，完整验收与归档见[任务看板](../tasks/README.md)。

同日确认的范围收敛：导入/撤销仅供具备全行编辑范围的管理身份准备数据；策略采用校验后原子生效，取消独立草稿生命周期；新后台任务不携带用户 IP，时间条件按实际执行时评估。以下正文为这些决定的唯一详细口径。

当前已交付元数据发布、策略配置、真实 SQL 行列过滤、CSV 导入及在线端到端验证；一次性快照已验收，内部定时任务已实现并验收。交付状态见[任务看板](../tasks/README.md)与[现役服务设计](services/example-service.md)。[example DDL](schema/example-service.sql)是当前独立业务库的唯一建表来源。

## 2. 最小业务载体

| 对象 | 最小功能 | 演示目的 |
|---|---|---|
| 报表资源 | 名称、稳定编码、所属数据集、启停及操作权限 | 资源实例、类型级操作、依赖上下文 |
| 销售记录 | CSV 入库、详情、分页、修改业务备注、批量操作 | 真实 SQL 行过滤与读写一致性 |
| 报表字段资源 | 报表内字段登记、读取/编辑授权、字段生命周期 | 同名字段跨报表隔离，列范围受报表上下文约束 |
| 数据权限策略 | 字段目录、行谓词与列投影映射、发布版本、审计 | 修改配置即改变行列权限，无需改业务代码 |
| 自定义定时任务 | 创建/修改 cron、启停、手动触发、执行记录、结果领取 | 执行时权限重查、幂等、重试和重启恢复 |

报表只是受保护的数据入口，不提供销售额计算、聚合图表、指标体系、报表设计器。没有新业务前端；角色、授权、条件等在已有 IAM 管理台配置，example 通过 POST API、可执行脚本和请求样例操作。脚本读取运行时用户 ID/资源 ID，不要求操作者手工猜 ID。

演示闭环：准备独立租户和用户 → 创建报表/字段并同步资源及操作 → 配置行列映射 → 为数据准备身份授予所需权限 → 导入 CSV → 为演示身份授予受限行列权限 → 以不同用户调用同一 API → 修改授权或策略后再调用 → 执行定时任务 → 重启并验证记录、配置和执行结果。准备身份与演示身份分开，不能让 bootstrap 管理员的全量授权覆盖负向场景。

## 3. 数据与导入

首版固定一张业务记录表，字段为 recordCode、ownerUserId、teamCode、departmentCode、regionCode、saleDate、productName、amount、remark。金额只是可返回的业务字段，不做统计分析。日期和 decimal 类型校验仍需真实落库。

- CSV 模板与示例由字段目录生成或校验，导入明确目标报表；ownerUserId 为演示脚本真实创建的 LOCAL_USER ID。导入/撤销仅面向数据准备管理身份，必须同时具备独立数据维护权限、目标报表 DATA_EDIT、该报表行范围 DATA_EDIT 格的 ALL，以及涉及业务字段的编辑权限。这里的管理员由权限组合判定，不按角色名或管理员标志绕过检查。
- 仅持 INSTANCE 行范围者即使覆盖当前批次所有记录，也不能导入或撤销；EMPTY/DENIED/配置故障同样拒绝。撤销从批次持久化信息取得来源报表及涉及字段，不能通过请求替换为另一份授权更宽的报表。普通用户只通过查询、单条/批量备注修改演示行权限，不新增按行范围校验新记录的导入流程。
- ownerUserId/teamCode/departmentCode 是记录的业务归属，不由角色名称推导。首版不建设销售人员账号绑定页、影子账号目录或团队成员管理；身份源仍是 AccessMesh。
- 归属值在导入时固定；记录接口只允许修改备注等明确白名单业务字段，不借修改备注转移所有者/团队/部门。归属订正通过受控撤销批次并重导，未来扩展单独定义。
- 整批校验、整批提交；同租户有效 recordCode 唯一。每次主动导入携带脚本自动生成的 `importKey`，网络重试沿用该号，不以文件摘要单独判断一次新操作。不同导入与已有有效记录冲突整批拒绝，错误包含行号与字段，不静默跳过。请求重放与撤销后重导的身份规则见下文。
- 文件与行数上限见[执行预算](#execution-budgets)；可通过导入记录查看结果并撤销整个批次。导入/撤销使用同一数据库串行边界，记录与批次同事务提交。报表/字段/范围资源已在准备阶段登记，不为每条销售记录创建 IAM 资源或无消费方的发布事件。
- 未使用的范围目录项或未知用户不能被误解释成“所有人”；只持有 SELF、但无归属自己的记录时返回空集合。
- 不长期保留上传文件，批次保留摘要、操作者、行数和状态；示例 CSV 显式导入，不在服务启动时隐式灌数据。重置脚本只操作明确的演示租户与样本批次，不清空其他租户。
- 导入准备拆成报表/字段元数据登记、资源发布及授权、数据确认入库，避免“未入库就没有字段资源，未授权又不能入库”的循环。模板/表头映射只引用该报表已发布字段；未知新增列先登记并授权，不在导入时默认开放。错误反馈不回显无读取权限字段的值。

<a id="import-idempotency"></a>
### 导入请求号与重导

2026-10-19 用户确认采用 `importKey` 区分网络重试与主动重新导入。脚本在一次主动导入开始时生成唯一请求号，并在该次操作的重试中沿用；主动执行新的导入时生成新号，无需操作者手工填写。

- 同租户同 `importKey` 唯一，批次绑定来源报表、文件摘要及原操作者；同号换文件或换目标报表拒绝，不覆盖原批次。请求号不是权限凭证，重放不得绕过当前导入权限或泄漏其他操作者的批次信息。
- 同号重试读取原批次当前结果，不重复写入业务记录。批次已撤销时返回已撤销状态，不因迟到的重试恢复数据。
- 撤销后主动重导使用新号，重新执行当前权限、字段、数据校验和数据库事务。新号不绕过有效 recordCode 唯一约束；旧记录仍有效时重复导入整批拒绝。
- 请求号唯一约束与成功批次、业务记录写入在同一本地事务内闭合；事务未提交的请求重试可重新执行，不能仅凭内存已接收状态宣称导入成功。并发同号请求不能落下重复批次或重复记录。
- 只在导入批次中保存请求号与摘要，不建设通用幂等平台。批次撤销后保留其请求号记录，避免同号被当成从未使用的新操作。

<a id="dynamic-policy"></a>
## 4. 动态数据权限配置

### 4.1 两个职责

AccessMesh 决定主体具有哪些主资源操作及有效范围，继续复用 `query-scopes` 的 DIRECT ∪ DEPENDENT、条件与互斥规则。example 将行范围映射到 WHERE，将字段范围映射到 SELECT/允许写入列，不另写角色或授权引擎。

配置持久化并通过受保护 API 更新，不能仅改 YAML 后重启。Java 只提供有界的字段解析、谓词校验和参数化 SQL 编译器；不包含 `if 本人/团队/部门`、按角色名分支或部门 ID 常量。

### 4.2 配置内容

| 配置 | 内容 | 不变量 |
|---|---|---|
| 数据集字段目录 | 逻辑字段名、现有数据库列、数据类型、允许比较操作 | 目标表由服务端数据集注册限定；列须存在且获准，禁止请求带 SQL 标识符 |
| 报表字段目录 | 报表身份、稳定 fieldId/fieldKey、数据集字段引用、字段资源业务键、状态 | 字段目录允许被查询不等于当前用户有字段读取权限；同名字段跨报表独立 |
| 操作绑定 | 数据集业务动作对应主资源类型/操作、范围类型/操作 | 同一次请求只使用服务端已发布配置，不从客户端选择任意策略 |
| 范围谓词 | 范围资源业务键对应的字段、EQ/IN、值来源及值 | 值来源限可信主体属性和类型匹配的配置常量；首版不执行脚本/SpEL/SQL |
| 策略版本 | 完整配置校验、版本 CAS、原子生效、操作者与变更摘要 | 同一查询/写操作固定一个生效版本，失败不替换现行版本；无独立草稿存储 |

行范围默认使用自有类型 `DEMO_DATA_SCOPE`，字段范围使用独立类型 `DEMO_REPORT_FIELD`。本人/团队/部门共用行谓词解释器，字段资源共用列投影解释器；两种范围按类型分格，不混作 OR。固定主类型/主操作见 §10；范围类型/操作及字段映射从已发布配置加载。资源业务键包括 resourceTypeCode/resourceCode/codeType，匹配时使用结构化键，不靠分隔符反解。

同租户的报表、字段与行范围类型按用途隔离，字段/范围保留自定义类型名；登记入口共同约束见[类型用途契约](example-service-api-contract.md#resource-type-purposes)。这不改变行范围与字段授权动态配置的能力。

配置形态以[专属 API 契约](example-service-api-contract.md#policy)为准，由 fields、read、edit 和 bindings 组成。[准备脚本](../../tools/init-example-permission-demo.ps1)提供本人、团队、部门、地区的可执行初始配置；读取当前策略后按版本提交修改，不复制另一套配置协议。

“本人”由 `SUBJECT_ID` 从可信认证上下文取值，不接受客户端 ownerUserId 作为当前主体；团队/部门只是不同字段配置。增加“地区 R1”范围，只需登记/授权对应资源并配置 regionCode=R1，无需修改 Java 或重新发布服务。

同一已授权资源项的 predicates 取 AND，不同有效资源项取 OR，保持授权范围的并集；最终再与用户筛选取 AND。用户筛选永远不能扩大权限。配置可表达“部门 D1 且团队 T1”，也可通过两个已授权资源项表达“本人或团队 T1”。不提供不受限的嵌套规则语言。

范围绑定业务键必须唯一，predicates 不能为空；拒绝未知值来源、字段/值类型不匹配与超出预算的配置。缺少字段或空谓词不能编译成恒真条件。全范围只能来自引擎明确返回的 ALL，不能用损坏配置兜底。

配置可改变授权资源的业务含义，属于安全管理面：维护/发布需独立 `DEMO_POLICY:MANAGE` 权限，记录版本、操作者、目标、变更摘要；普通业务调用者不能修改字段映射或提交自定义谓词。租户约束、有效批次和软删除约束是强制不变量，不可配置关闭。禁止使用 tenantId 等系统隔离字段作为可改写映射。

策略 API 只需读取当前配置，以及提交完整配置并校验生效。提交带期望当前版本，服务端完成字段/类型/身份/预算校验后，以 CAS 在同一事务写入新版本、切换生效引用并记录审计；非法配置或版本竞争均不改变当前版本。没有保存草稿、审批、分步发布或独立回滚流程；需要恢复历史内容时，将其作为完整配置重新校验并生成新版本。文中的“发布”均指这一单次原子生效动作。

新增现有字段的范围映射无需改代码；新增物理业务字段仍可能需要 DDL/导入字段目录调整，不能承诺“任意新业务结构零改动”。首版动态能力边界是范围映射、值来源和受支持谓词，不是任意 SQL 平台。

### 4.3 生效与四态

- 每次执行按可信租户取得已发布版本，无版本或非法绑定失败关闭；不新增策略缓存。发布后开始的查询读取新版本；进行中的查询保持其固定版本，响应给出版本便于复现。
- 先核实主操作命中及行、字段预期范围格分别唯一、完整，再消费结果；不以 HTTP 200 或非空响应判为成功。以下行谓词语义与 §4.4 字段语义共同适用。
- INSTANCE：有效范围项均找到精确、类型正确的映射后，参数化编译并下推到 SQL。任何未知项都失败关闭，不忽略坏项来获得部分成功。
- ALL：本范围类型表示该数据集全范围，跳过可配置范围谓词，仍强制 tenantId、批次有效性、软删与用户筛选；授权页面/脚本明确其全数据含义。
- EMPTY：返回空结果，不查询业务记录表；DENIED：返回拒绝，不查询业务记录表。读取本地配置和报表元数据不算业务事实取数。
- 鉴权服务故障、缺格、未知模式、非法字段/操作符/值类型均返回错误，不降级全量、不伪装空态。
- 列表、详情、分页 total、批量操作、写操作、异步快照/导出共用同一策略解释器。分页在数据库执行，不先全量取出再内存过滤。

<a id="field-permissions"></a>
### 4.4 基于特定报表的字段权限

#### 字段身份与授权上下文

导入报表的每个可暴露业务字段登记为 `DEMO_REPORT_FIELD` 资源。业务归属唯一键为 `(tenantId, reportId, fieldId)`，映射到该报表稳定 fieldKey 与已登记的数据集字段；对外使用不透明、不可复用的资源编码，不能仅以 `amount` 等列名全局寻址。两个报表即使引用同一底层数据集、都含 amount，也各自有字段资源和授权。

持久化基础以字段主键的十进制文本生成 resourceCode，生成列不可被请求覆盖；软删保留原主键，新建同名字段使用新主键，因此不会复用旧授权身份。调用方将该编码视为不透明值，完整资源键仍由类型/codeType 与该编码共同组成，不把 IAM 内部资源 ID 当作本地 fieldId。

典型授权为“报表 A 的 DATA_READ 主权限 → A.amount 的 DATA_READ 子权限”，编辑同理使用 DATA_EDIT。初始化明确配置现役 SUB_PERM 允许的字段资源类型，不依赖缺省放行。这里的报表→字段关系是业务归属和 depend_on 授权上下文，**不是**跨资源类型的资源树父边；不设置违反现役同类型树约束的 parentResourceCode。

运行时从已验证的本地报表取得真实身份和所属字段，作为 query-scopes 的主资源上下文；同次读取请求使用 `parentOperationCodes=[DATA_READ]`，请求行范围与字段范围两类的 DATA_READ 格。修改用 DATA_EDIT；导出额外校验 EXPORT，取数仍用 DATA_READ 行列范围。主类型/主操作固定，范围绑定保持动态配置，不新增一套授权算法。

演示默认采用报表主权限下的字段子权限。现有 DIRECT 或类型级 ALL 仍按引擎语义评估，但结果只能投影当前报表的字段：已知属于其他报表的字段项排除，不能按同名套用；未知资源映射、类型异常或缺格失败关闭。报表主权限未通过时，任何字段授权都不独立打开该报表。

#### 行、列共同生效

最终可返回内容 = 当前报表业务数据 ∩ 有效行范围，再投影有效可读字段。行范围全部允许不代表字段全开放；字段全部允许也不取消行限制。首版字段集合对本次报表结果统一生效，不表达“同一列在不同行有不同权限”的单元格授权。

| 字段格结果 | 业务行为 |
|---|---|
| INSTANCE | 精确映射到当前报表启用字段，与请求列相交；无效/未知字段不宽松放行 |
| ALL | 仅展开当前报表当前已登记且启用的业务字段，保留行过滤和系统字段禁出边界 |
| EMPTY | 返回明确“无可见字段”空态，不取业务记录，不附带真实行总数或隐藏字段值 |
| DENIED | 拒绝本次对应数据操作，不取业务记录 |

任一必要维度 DENIED 即拒绝；不存在拒绝/配置错误但任一维度 EMPTY，则不查询业务记录。INSTANCE 排除其他报表字段后若为空，按无可见字段处理。没有字段授权不回退全部字段；新增字段缺省不可见，显式授予字段 ALL 的主体则按其明确全字段语义获得新登记字段。

- 查询未指定列时只返回可读列；显式请求包含不可读列时整次拒绝，不静默扩大或悄悄忽略。拒绝消息不区分未知字段与无权字段的内部存在性。
- SQL 使用明确投影列，禁止 SELECT * 后才靠序列化隐藏；已授权列的真实 NULL 保留字段键与空值，整行可读投影均为 NULL 时仍保留这条可见记录；无权字段完全不出现在结果列描述、记录键/值或 CSV 表头中，不以 null 冒充脱敏。业务 recordCode 等字段也不例外；技术 requestId/策略版本不属于业务字段。
- 2026-10-19 确认：详情与单条/批量修改通过 `recordCode` 定位，不新增字段权限之外的 rowId。没有 recordCode 读权时列表不返回编号；从外部流程已知编号的调用者可以提交请求，但仍须通过该次操作的报表、行范围和字段权限检查。记录定位不视为用户自定义筛选，不额外强制编辑者获得编号读权，也不在结果或错误中自动回显编号。“先列表再修改”的演示明确授予 recordCode 读权，不用管理员旁路补齐。
- 用户筛选、排序、搜索、去重候选只能使用有读取权限且字段配置允许的列，避免通过 amount 的条件/排序/total 推测隐藏金额。服务端授权谓词可以内部使用 ownerUserId 等未展示列，只用于强制范围过滤，不向响应/错误暴露其值。
- 字段可读不代表可写。修改需报表 DATA_EDIT、对应行编辑范围及全部提交字段的 DATA_EDIT；还须满足业务字段可编辑白名单。任一字段无权或不可编辑则整次/整批拒绝、事务零副作用；不得把未授权属性绑定进实体后统一更新。
- 写入成功不自动回传字段值；没有读取权限的写入者只得到操作结果。SQL RETURNING、批量结果、导入错误和任务摘要同样使用允许输出字段，不能通过写后回显或错误原文泄漏无读权值。
- CSV 导入同样校验所有实际写入业务列的字段编辑权；字段注册/数据维护权限不构成读权。预览若返回字段值，须另取 DATA_READ 字段集合；无读权列不回显，确认入库仍按编辑权判断。必填列缺失或无权写入时整批拒绝，不以默认值绕过。
- 导出与定时任务执行时重新取得行、字段范围，结果及表头只包含当次可读字段，并记录报表字段目录版本、策略版本和实际输出列。任务显式选列被撤权则拒绝；未指定列则按执行时可读列投影，无可读列不生成数据产物。
- 已经完成的快照仍遵守既有“产物归提交者”领取边界，不在领取时重新补取/补列，也不声称字段撤权会追溯抹除已生成内容。执行前撤权和生成完成后撤权分开验收。

#### 字段生命周期与版本

字段目录持久化且版本化，与策略映射一起校验。创建/新增字段后，资源发布成功且授权到位才可消费；改显示名不改身份，不能把已有字段资源悄悄重绑到另一个物理列。删除字段立即退出本地投影/写入，异步回收其资源；重新新增同名字段取得新身份，不复活旧授权。配置引用已删除字段时拒绝发布或拒绝执行，不退回全字段。

初始化脚本先完成报表及字段声明、SYNC 和授权，再导入数据。读取、导入、写入与任务执行固定目录/策略版本，提交或执行前发现目录不兼容变化则失败并要求重新发起，不按新的列含义解释旧请求。长期任务的显式选列在创建/修改时解析为稳定 fieldId，筛选/排序也保存其字段身份；同名删除重建不按名称自动重绑。默认列模式与显式空列清单区分，显式空清单拒绝，省略清单才表示执行时选择当前可读列。

## 5. 最小 API 与权限演示

所有入口 POST + JSON DTO；CSV 上传与受保护下载沿仓库已允许的例外。新增业务族可采用 `/api/example/demo-data/**`，保留现有 hello/report 探针直到独有证据迁移完成；不并列建设两个真实业务产品。

请求、响应与错误语义在[example API 契约](example-service-api-contract.md)定稿；该文为采纳目标，不表示接口已上线。

| 能力 | 最小动作 | 必须验证 |
|---|---|---|
| 数据准备 | 报表字段声明、导入、批次查询、撤销 | 全行编辑范围的管理身份、字段编辑/预览读权、租户隔离、幂等 |
| 主资源 | 创建、详情、启停 | 类型级 CREATE、实例级 VIEW/UPDATE、真实存在性 |
| 记录读取 | 分页、详情、批量查看、授权字段目录 | Gateway 准入不等于最终允许；行过滤与列投影同时生效 |
| 记录修改 | 单条/批量修改备注 | DATA_EDIT 主操作、行范围、字段权限及业务可编辑性均通过 |
| 策略配置 | 读取、提交完整配置并校验生效 | 独立管理权限、版本 CAS、无效配置不替换旧版本 |
| 任务 | 创建/修改/启停/触发/记录/结果 | 调度权限与实际数据权限分离，执行时重查 |

写操作只修改当前请求触达字段。在真实数据库 UPDATE 中保留 tenantId、有效状态、业务 ID 和权限谓词；不得先查 A 的权限再写 B。批量修改默认整批全允许才提交，任一目标无权/不存在则整体失败且无部分修改；批量查看可逐项返回允许/拒绝。SQL 事务保证结果原子，远端权限查询在事务外，不宣称与授权中心形成分布式原子事务。

操作绑定可为 DATA_READ 和 DATA_EDIT 配置不同的行、字段范围；修改路径复用编译器，不把可读行/列自动当可写行/列。固定用户上下文由网关验签，M2M 凭证按可信租户选择，DTO 不允许自报主体或租户。

资源启停与业务状态均明确校验；任务停用阻止新触发，并在执行前再次核对。不能为了某个演示方便增加管理员绕过或关闭 Gateway 签名校验。

## 6. example 内部定时任务与持久化

### 6.1 现有能力与复用边界

access-service 当前任务调用仅支持本进程 `@JobInvocable bean.method(TaskExecutionContext)`；该上下文包含租户、jobId、executionKey、attempt 和 scheduledTime。虽然 SysJob 有 runAsUserId 字段，当前调用上下文本身不携带它，不能假设该字段已构成 example 的执行授权。

用户选择 example 内部调度。本计划不引入跨服务任务桥接，不复制整个 access 任务平台，不依赖其内部 Bean/Mapper，也不修改其任务契约。复用成熟的执行键、数据库幂等、尝试号防旧结果覆盖的设计原则；实现用 Spring 调度和 example 自有持久化表，首版明确单实例运行。

### 6.2 演示任务

首版自定义任务固定为“按指定报表与筛选生成授权数据快照/CSV”。用户可配置名称、cron、报表、筛选和启停；目标方法/URL/SQL 不可任意配置。生成结果是原始授权记录，不做统计分析。

- 创建任务时执行主体固定为可信创建者，不能请求指定其他 runAs 用户；修改任务不得替换其执行主体。任务操作需要任务管理权限，报表快照另需 EXPORT/DATA_READ。首版不支持代他人维护/触发任务：查询定义、修改、启停、触发、查看记录或领取结果，均要求可信租户和操作者与任务创建者一致，再检查相应任务操作权限；他人任务与不存在使用一致拒绝语义。拥有任务管理权限不能借修改他人筛选或报表，让后台按他人身份执行。
- 初始化为任务配置独立 `DEMO_TASK` 操作族（CREATE/VIEW/UPDATE/ENABLE/TRIGGER），首版采用类型级操作授权加任务本人归属，不增加每条任务的远端资源同步。自动与手动执行统一检查创建者当前 TRIGGER 及报表 EXPORT/DATA_READ；领取已完成结果使用任务 VIEW 与归属，不重新检查源报表权限。控制权限、执行权限和结果领取三处分别有负向证据。
- cron 按 UTC，保存/修改即时校验；每个 `(tenantId,taskId,scheduledTime)` 对应唯一执行记录及稳定 executionKey，手动触发为独立执行。重试沿用执行键，不新建业务结果。
- 任务配置修改后只影响未来触发；执行记录冻结报表身份、筛选及其字段身份、可选 fieldId 清单和任务版本。执行开始重新读取当前已发布数据策略、报表字段目录与当前行列权限，记录实际版本和输出列；显式选列变化按 §4.4 拒绝规则处理。尚未取数的重试重新鉴权；已经原子完成的执行返回既有完成状态，不再生成第二份数据。定时与手动触发共用同一执行入口，不能用旧 HTTP 身份头、旧 Bearer 或内存 ThreadLocal 充当后台身份。
- 用户被停用、权限被撤销、服务凭证失效或任务停用，后续执行应拒绝/跳过；不得只验证“任务创建时有权”。停止任务/撤权与已经进行中的取数不存在跨服务强原子承诺，按现行鉴权生效窗口和本地检查边界验收。
- 本计划新增后台快照/定时任务的自动、手动及重试执行均不携带用户 clientIp：不沿用提交来源 IP，不以任务主机 IP 代替，也不从旧请求头恢复。IP 条件缺上下文时不满足，依现役引擎返回 DENIED 或 EMPTY；若另有有效授权，仍按现役合并语义判定，不能自行改成“出现任何 IP 条件就整次拒绝”。时间条件由鉴权服务按本次实际执行时间评估，不使用任务创建时间或计划触发时间伪装当前时间。现有旧一次性导出保存提交 IP 的实现不在本次改动范围。

该语义造成的“在线 IP 条件通过、后台不满足”限制及后续重访条件保留于 [T-ACCESS-143](../archive/2026-10-20/tasks/T-ACCESS-143.md#task-ip-context-limit)，不因本次定案丢失，也不据此放宽当前权限检查。
- 结果按[执行预算](#execution-budgets)限制行数与字节，超限失败并提示缩小筛选；结果直接持久化在业务库，避免首版再建设文件卷和文件管理。CSV 导出沿既有转义与公式防护规则。
- 任务定义、执行状态、尝试号、错误摘要及成功结果持久化。服务重启加载启用任务并处理未完成执行；通过 CAS/尝试号防旧执行覆盖新结果，唯一执行键防重复落结果。
- 失败重试有上限；最终失败可见。权限拒绝为业务终态，不无限重试；技术故障才按既定预算重试。停机期间默认不补发全部遗漏 cron，只恢复已有未完成记录；恢复与重试规则见本节及执行预算。
- 已完成结果仍按[现役导出归属边界](access-service-api-contract.md#completed-export-ownership)由原提交者领取，检查租户/用户归属和接口准入；不因之后源权限撤销重新生成或自动删除已完成内容。保留期与有界清理通过内部维护调度执行，维护不读取或再分发业务数据。

执行状态最低闭合为 PENDING → RUNNING → SUCCESS / DENIED / EMPTY / SKIPPED / FAILED；技术故障在预算内以同键回到 PENDING，超限为 FAILED。行/字段 EMPTY 或有效查询零记录为 EMPTY，不生成可下载产物；任务执行前停用为 SKIPPED；权限拒绝为 DENIED；SUCCESS 到期转 EXPIRED。状态接口可读到受控原因，但不输出未授权字段值、凭证或原始异常。

仅连接超时、可重试数据库故障等暂态失败进入有限重试；引擎权限拒绝为 DENIED，非法策略/字段身份失效/服务凭证明确停用或认证失败为可排查 FAILED，不无限重试。不能把所有鉴权调用异常都当作用户无权，也不能每次重试新建执行键绕过上限。

抢占时增加 attempt，结果写入与 SUCCESS 状态在同一 PG 事务、按当前 attempt 条件提交；结果记录以执行键唯一。同进程重复触发、崩溃后恢复和超时尝试均不得重复提交结果。单实例重启后对遗留 RUNNING 重新排队，再次抢占生成新 attempt；已经 SUCCESS 的记录只读取已存结果。验收须在结果事务提交前、提交后分别模拟故障，验证重试与不重做的区别。

一次性快照使用 `demo_execution` 保存冻结的 Selection，执行时重新鉴权并在本地一致快照中调用共用数据 DomainService；CSV 格式与审计复用 common 的有界写入器。抢占/提交使用执行键和 attempt 条件更新，字节与 SUCCESS 单条更新同事务；提交确认丢失后不得覆盖已提交的终态。单实例 worker 启动先恢复未完成记录，再开始抢占；每次维护最多清理 100 条到期产物。执行状态/本人下载不重查源报表范围，不延长期限。任务定义、本人控制、cron 接线已由 T-ACCESS-143 实现并验收；定时和手动触发共用上述执行器。

### 6.3 持久化验收

数据库负责保存，定时任务负责触发、恢复、重试和有界清理，调度不能替代持久化。重启验收包括：数据/策略/任务仍存在、未完成执行可恢复、同执行键只出现一份结果、旧尝试不能覆盖新尝试、用户撤权后下一次不再产出数据。首版不独立建设备份平台或跨版本升级系统；新增持久数据仍应按部署规范备份，不将“可重复演示”理解为可任意清库。

## 7. 存储与实现边界

独立 example_db 与数据库账号，MyBatis-Flex/PostgreSQL 沿项目技术栈，不读取 IAM 内部表。逻辑实体为报表、报表字段与资源映射、业务记录、导入批次、数据集字段目录、策略版本/范围绑定、待发布资源、定时任务、执行记录与有界结果；报表字段归属/身份和目录版本必须有持久约束，不能只放内存映射。同生命周期结构按首版表结构合并，不为概念各造一层框架。唯一可执行 DDL 由 [example schema](schema/example-service.sql)维护，T-ACCESS-137 已完成原样 PG 验证；实际环境只按[业务库初始化说明](../ops/example-database.md)在空库执行，不由服务隐式建表。

资源通过现有 SYNC 通道登记，类型定义和操作仍由租户管理员经既有管理 API 创建，类型来源明确归 example。待发布事件与本地业务写入同事务，事务外发请求，重试同载荷/版本；发布未完成不冒充资源已可授权。政策规则修改不直接改用户授权，所有授权仍在 AccessMesh。

Controller → AppService → DomainService → Mapper；事务在 AppService。本地唯一性、CAS、行锁优先，不为示例新增 Redis 依赖。按[并发规范](project-rules.md#backend-concurrency)枚举竞争入口；所有远程查询/发布在本地写事务之外。字段类型、节点/参数数量、SQL 时间和分页设置硬上限，禁止原始 SQL 或可执行表达式。

配置发布是安全边界：原子切换版本，记录变更，校验失败保留旧版本；恶意字段、类型错误、循环/过量结构均拒绝。不缓存主体授权结果来掩盖撤权。结果记录的 requestId、任务 executionKey、策略版本和允许/拒绝原因用于复现，不开放外部 TRACE 或新权限排障页面。

### 7.1 实施结构

以下结构由 T-ACCESS-137 实施。数据库表列、索引与约束最终只在 example schema 维护，不另建重复 DDL。

| 持久事实 | 最小承载 | 关键约束 |
|---|---|---|
| 固定数据集及当前策略引用 | 数据集控制行 | 按租户、datasetCode 唯一；承载当前版本和该数据集写入的共同串行边界 |
| 报表与报表字段 | 报表表、字段表 | 有效报表编码唯一；字段归属租户/报表，保留稳定 fieldId、远端资源业务键、目录版本，删除不复用身份 |
| 策略版本 | 完整配置版本表 | 同租户同数据集版本唯一、历史版本不可改写；配置及变更摘要与当前引用同事务提交 |
| 业务记录与导入批次 | 记录表、批次表 | 有效 recordCode 租户内唯一；importKey 租户内唯一；保存来源报表、文件摘要和实际导入字段身份 |
| 待发布资源事实 | 待发布记录表 | 业务事实与事件同事务；相同资源/源版本唯一；按存储载荷重放，不临时重建为另一版本 |
| 自定义任务与执行 | 任务表、执行表 | 执行主体不可替换；定时触发时刻唯一；执行键唯一；结果字节直接存执行记录，避免另建文件系统或结果管理实体 |

物理数据集字段与 SQL 列的可信对应由服务端有限目录维护；运行时策略只引用逻辑字段，不接受 SQL 标识符。报表字段指向该目录，新增现有字段的行范围仍只改配置；新增物理列需要正常 DDL/代码变更。

并发入口按以下共同不变量实施，不以单实例为理由取消数据库约束：

| 竞争入口 | 共同保障 |
|---|---|
| 导入、撤销、备注修改、策略版本切换和字段目录变更 | 同租户数据集控制行在实际事务内串行；锁后重新读取版本与有效状态。捕获的授权/目录与当前本地版本不兼容则失败，不能按新配置解释旧请求 |
| 同号导入及不同批次同码 | importKey/有效 recordCode 唯一约束兜底；批次与全部记录同事务；撤销保留请求号事实 |
| 资源更新与重试发布 | 本地单调源版本、持久化原载荷和现役 sync 旧版本防护；远程发送不在本地事务内 |
| 任务修改/启停、触发/抢占、结果完成与到期清理 | 本人归属、任务版本/有效状态校验、执行键唯一及 attempt 条件更新；结果和 SUCCESS 同事务；到期只处理成功产物，不覆盖运行尝试 |

涉及多行的路径统一先数据集控制行，再报表/字段，再批次/业务记录；同类多目标按稳定 ID 排序。锁内读取需实际访问数据库，不能复用 MyBatis 一级缓存中的旧实体。读分页在本地只读一致快照内读取 items/total，所有远程授权先完成；这不形成与 AccessMesh 的分布式快照或即时撤权保证。

### 7.2 PG 测试复用出口

为 access 与 example 共用的容器生命周期/fork 隔离代码使用仓库共享测试源码目录，由两个模块以现有 build-helper 插件的 test-source 接入；不发布新 Maven 模块或 access-service test-jar，不进入生产源码集。Testcontainers 依赖分别保持在原 access 和新增 example 的 test scope 内，不扩大到其他模块。

原 `ItInfra` 保留 access 侧门面及其模板/租户初始化、Redis 注册；抽离其 PG 容器、fork 槽位及隔离建库部分给真实的两个使用者。example 只消费 PG，按 example 原样 DDL 建类库；不启动 Redis、不加载 IAM schema/租户基线。现有 access 用例不需要逐类改调用方式。

example 使用独立 `testcontainers` execution，沿用 skipTestcontainers、heavy 与 fork 进程隔离规则；不与普通上下文测试混跑，也不把跨服务 E2E 移回服务模块。时区映射按工程规范 §7.4 在 example 配置同等 TypeHandler，不为此把 ORM 依赖上提 common。具体受影响证据与现状见[实施前核对](../archive/2026-10-20/tasks/evidence/example-permission-demo/implementation-baseline.md)。

当前持久层 Mapper 使用显式 tenantId 条件及同租户父对象关联；生成 SQL 的租户工厂拒绝未建立可信上下文的调用，不提供无租户回退。跨记录事务通过 Flex 管理的 Mapper 连接执行，不能混用独立 JDBC 连接来假定原子性。实际表约束、条件插入与映射验证由 T-ACCESS-137 承接；T-ACCESS-139 已接入元数据 AppService/DomainService、共同数据集行锁及事务内待发布事件，事务外发送，源版本条件回写就绪状态。查询、备注修改、导入与持久任务均复用这些本地身份和串行边界，已通过 PG 与真实 E2E 验证。

<a id="scenarios"></a>
## 8. 场景包与验收

所有数值是拟议演示样本；脚本创建身份后回填真实 ID。记录 A 属于用户甲/T1/D1/R1，B 属于用户乙/T1/D1/R2，C 属于用户丙/T2/D1/R1，D 属于用户丁/T3/D2/R2。另一租户有相同 recordCode。

| 场景 | 可观察结果 |
|---|---|
| 无权 → 授权 → 撤销 → 重授 | Gateway 与业务最终检查分别显示允许/拒绝，不能仅看 HTTP 200 |
| 本人/团队/部门 | 甲获本人只见 A；T1 见 A/B；D1 见 A/B/C；本人+T1 不重复 |
| 动态扩展地区 | 仅登记/授权 R1 范围并发布 regionCode 映射，见 A/C；不改 Java、不重启 |
| 策略更新 | 同一授权资源从一个已允许配置换为另一个，发布前后返回记录与策略版本可解释；非法发布保持旧版 |
| 父资源上下文 | 只绑定报表 A 的范围，在报表 B 不生效；伪造父上下文被业务归属检查拒绝 |
| 条件与互斥 | 使用现有时间/IP 条件和冲突规则得到不同判定，业务不自行实现这些算法 |
| 四态 | INSTANCE 精确行、ALL 仍隔离租户、EMPTY 不取业务数据、DENIED 拒绝 |
| 读写区别 | DATA_READ 允许而 DATA_EDIT 拒绝；混合有权/无权批量修改整体无副作用 |
| 报表字段隔离 | 报表 A、B 同含 amount；只授 A.amount 不使 B.amount 可读，即使两表引用同一数据集 |
| 行列交集 | 用户只获 T1 行与 recordCode/productName 字段，返回 A/B 且没有 amount 的字段描述、键、值或导出表头 |
| 字段读写与推测 | amount 不可读时，按金额筛选/排序拒绝；remark 可读但无编辑权时修改拒绝；非法混合字段更新全部回滚 |
| 导入字段权限 | 只有数据维护权而缺 amount 编辑权，带 amount 的 CSV 整批拒绝；新增列先登记授权，不默认开放 |
| 导入行范围 | 有维护权及字段编辑权但只有 T1 行范围，导入/撤销均拒绝；全行 ALL 且所需字段编辑权齐备时才允许 |
| 字段四态与生命周期 | 行 ALL 不放开列、字段 ALL 不放开行；无可见列不取数；删后同名新增不继承旧字段授权 |
| 任务字段变化 | 执行前撤销选定字段拒绝产出，默认选列只输出当前可读列；已完成产物按原归属领取且不补列 |
| 服务身份 | 缺租户凭证、凭证停用、伪造身份头、跨租户同码均拒绝 |
| 定时执行 | 创建后撤权，执行时拒绝；数据库故障重试同键，重启不重复产出 |
| 后台条件上下文 | 仅靠 IP 条件允许的在线请求可通过，而新后台任务因缺 IP 得到 DENIED/EMPTY、无产物；时间条件按实际执行时点变化 |
| 持久化 | 重启后记录、策略、资源关联、任务及成功结果可对账 |

条件、互斥、转授与资源继承优先使用已有测试/脚本证据，新增场景只补 example 接线缺口，不重新测试一整套引擎。转授演示可在既有 IAM 台完成，example 用请求结果验证 canGrant 的实际影响。

动态配置验收同时保留改动前后的应用产物摘要、进程启动时间、策略版本与实际记录 ID，证明结果变化来自配置/授权，而不是重新部署或特殊代码分支。

<a id="joint-demo"></a>
### 同一用户的联合演示主线

这条主线为必须交付的演示，不用彼此独立的单点测试替代。使用上表记录 A/B/C/D、报表甲/乙（同含 productName/amount）、普通用户甲及准备身份；普通用户不带 bootstrap 管理角色、字段 ALL、行 ALL 或未说明的继承授权。每步验证当前有效授权前提，避免撤回一条权限后仍被其他角色覆盖而产生假结论。

| 步骤 | 操作 | 必须观察到的结果 |
|---|---|---|
| 准备 | 注册报表/字段与行列映射，授准备身份维护权、报表 DATA_EDIT、行编辑 ALL 和导入字段编辑权，导入记录；给甲任务操作和报表甲 DATA_READ/EXPORT、T1 行、recordCode/productName 字段 | 准备记录和 IAM 资源可对账；甲无 amount，报表乙未授权；甲的局部行权限不能用于导入/撤销 |
| 在线读取 | 甲查询报表甲并尝试金额排序、改 remark、改为报表乙上下文 | 只返回 A/B 的授权列；排序、无编辑权写入及报表乙请求分别拒绝 |
| 首次定时执行 | 甲建显式选择 recordCode/productName 的任务并启用 | 在线与后台输出相同行列；记录 executionKey、attempt、策略/目录版本及输出列 |
| 行撤权 | T1 范围改为本人，等待现役撤权窗口内结果符合，再触发新执行 | 在线与新执行均只含 A；旧成功结果保持原内容，不补取数据 |
| 字段撤权 | 撤销 productName，在线默认列查询并运行显式选列任务 | 在线只剩 recordCode；显式选列任务为 DENIED，无产物 |
| 默认列任务 | 甲把任务改为省略选列清单，再触发新执行 | 新任务版本只输出 recordCode；旧执行请求和结果不被改写 |
| 恢复与字段隔离 | 重授报表甲 productName，再试报表乙同名字段 | 甲的后续执行恢复 A 的两列；乙的同名字段仍不能访问 |
| 任务归属 | 另一个拥有任务操作权限的用户尝试修改、触发、读取甲的任务 | 全部拒绝，不能借用甲的主体执行或读取结果 |
| 编辑正反例 | 给甲报表 DATA_EDIT、本人行编辑范围及 remark 编辑权；修改 A，再尝试混合修改 A/B | A 修改成功；混合批量整体失败，B 不变且 A 不被部分更新；无 remark 读权时写后仅返回操作结果 |
| 空范围与条件 | 按已有条件/互斥夹具产生 EMPTY，并分别对线上与任务执行 | 线上明确空态，任务 EMPTY，业务记录查询和产物写入均未发生 |
| 故障与重启 | 结果事务提交前故障后恢复，再模拟提交成功但确认丢失 | 前者同 executionKey 重查权限后重试，后者只返回既有结果；数据库只保留一份成功产物 |

API 演示等待可核对的状态和结果，不固定 sleep 后宣称撤权或恢复已生效。定向测试通过闩锁/执行闸门控制“提交后、执行前”和“结果提交前、提交后”，不新增生产调试后门。T-PERM-036 的普通用户在线行列、导入与双租户实证见[验收记录](../archive/2026-10-20/tasks/evidence/example-permission-demo/T-PERM-036.md)，T-ACCESS-141/143 证明同一执行器的快照/调度边界，T-ACCESS-142 的[联合场景包](../../example-service/examples/permission-demo-scenarios.md)与完整 E2E 串起同一用户验收，并保存实际执行观测。

交付一个按场景组织的 API 样例/PowerShell 脚本包及预期记录 ID 清单，不强制新增第三方工具依赖；每步检查 HTTP、信封与业务结果。准备/重置/反例均限定演示范围，秘密只在内存或忽略配置保存。

测试复用现有基础：配置编译用单测；原样 DDL、谓词 SQL、事务/幂等用 PG；跨服务场景只放 e2e。PG 生命周期已提取至 test-support，access 的 ItInfra 和 example 的 ExamplePgInfra 分别保留服务门面和执行轨，不依赖另一服务测试包或自建重复容器组。收口按仓库要求全量回归，不新增前端任务及不必要的浏览器门禁。

### 网关准入与主操作绑定

2026-10-19 用户确认：首版报表主类型固定为 DEMO_REPORT，读取/编辑/导出主操作分别固定为 DATA_READ / DATA_EDIT / EXPORT；接口声明与业务检查使用同源常量，不作为策略可编辑字段。报表元数据 CREATE/VIEW/UPDATE 同样采用固定主类型。该边界仅约束 example 演示接口，不限制 AccessMesh 平台创建其他类型或操作。

<a id="execution-budgets"></a>
### 首版容量与执行预算

以下硬上限与恢复参数于 2026-10-19 经用户确认，作为首版实施与验收依据。按演示样板定位给出有限边界，不用可配置的通用资源管理平台替代。

| 边界 | 上限 / 行为 | 实际影响 |
|---|---|---|
| CSV | 文件最多 10 MiB、每批最多 10,000 条记录 | 任一超限整批拒绝，不默默丢掉后半段 |
| 配置与行范围 | 完整配置最多 256 KiB；每版最多 256 个范围绑定，每个绑定最多 8 个 AND 条件，IN 最多 100 个值 | 本人/团队/部门/地区共用 EQ/IN；不同授权范围仍取 OR，无任意嵌套表达式 |
| 用户筛选与权限 SQL | 用户筛选最多 8 个 AND 条件，支持 EQ/IN；一次查询编译后的绑定参数总数最多 4,096，SQL 执行期限 5 秒 | 超预算返回明确失败，不忽略条件、不扩大行范围；系统租户约束始终保留 |
| 快照 | 最多 1,000 行，含表头和编码后的 CSV 最多 1 MiB | 任一超限整次 FAILED、无可领取的部分产物，提示缩小筛选 |
| cron | UTC 六段表达式，秒字段固定为 0 | 最密每分钟触发；不支持每秒执行，降低演示后台负载 |
| 技术重试 | 一次执行最多 3 次尝试（包含首次），失败后分别等待 10 秒、30 秒 | 同一 executionKey，重试重新鉴权；权限拒绝、非法配置、明确认证失败不进入自动重试 |
| 停机恢复 | 恢复已存在的未完成执行；停机时段没有创建执行记录的 cron 时刻不补发 | 重启不会补跑数小时遗漏任务；未来触发继续按 UTC 计划 |
| 成功结果 | SUCCESS 提交后保留 7 天，到期为 EXPIRED 并清除结果字节 | 执行键、状态与必要审计信息继续保留，防旧请求被误判为全新执行；已经领取的文件不受控于服务器清理 |

分页上限 200、全行管理导入、后台无用户 IP 等现行或已确认规则继续适用。资源发布重试的失败可见与人工重放安排见发布 API，不以任务成功状态替代资源发布成功。
