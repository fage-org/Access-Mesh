# 文件管理页面

## 目标与交付状态

2026-10-18 确认：文件作为标准能力补通，并交付最小文件管理页面。后端接通由 [T-ACCESS-116](../../archive/2026-10-18/tasks/T-ACCESS-116.md) 实施，页面由 [T-FE-078](../../archive/2026-10-18/tasks/T-FE-078.md) 实施。新建标准租户已有菜单、文件 API 准入及管理员授权；`/system/file` 消费真实接口。

接口、字段和安全语义以[文件契约 §17.1](../access-service-api-contract.md#contract-section-17-1)为唯一详细来源；默认授权见[固定图文件能力](../access-service-architecture.md#file-bootstrap-target)。

## 页面范围与布局

- 路由 `/system/file`，位于系统管理下，菜单名称“文件管理”；沿用服务端菜单下发与现有路由守卫，不添加独立导航机制。
- 使用现有列表页模式：分类筛选与操作栏、分页表格、轻量上传对话框、文件基本信息展示。动手写样式前按布局规则核对实际 DOM，复用既有表格、分页、消息和 CSS 变量。
- 展示原始文件名、业务分类、大小、MIME 类型、创建时间与可用操作；不将内部存储路径作为访问地址或公开链接。
- 分类沿用 `bizType`：常用值 `default/avatar/document/image`，允许输入符合现行格式的分类编码。不新增目录树、目录维护接口或全量分类目录读取权限；页面可从已有文件行识别实际分类。
- 上传单次选择一个文件；成功后刷新当前列表。下载、查看信息、单条删除构成最小操作集，不增加批量上传或批量操作工作台。

## 权限接线

- 页面能力使用现有有效权限码：`ADMIN_FILE:CREATE/VIEW/DELETE`。菜单和按钮仅提供交互提示，最终文件夹范围仍由服务端判定。
- VIEW 缺失时不请求文件列表或详情，不把拒绝显示为“暂无文件”；仍持 CREATE 的用户可以使用上传入口。持 VIEW 时列表只展示服务端裁剪后的文件，不在前端自行推算授权范围。
- 上传检查所选分类 CREATE；下载和详情检查文件所属分类 VIEW；删除检查所属分类 DELETE。拥有某分类权限不代表拥有其他分类权限，按钮可见也不能绕过服务端门禁。
- 租户管理员覆盖本租户全部分类，包括其他用户上传的文件，并可经现有授权页把分类权限分配给角色；普通用户不自动获得文件权限。不存在“仅看自己上传文件”的新增规则。

## 请求与交互

- 在 `frontend/src/api/` 增加文件 API 封装，复用公共 HTTP 客户端。上传使用 FormData，由客户端正确生成 multipart boundary，避免继承 JSON Content-Type；保留 Cookie、页面会话标记和 CSRF 头。
- 文件响应新增的 `bizType` 从真实 `bucket_name` 映射；登记前后端 DTO 对账。文件名和类型展示使用契约字段，不通过解析存储路径猜测分类。
- 下载使用鉴权 POST 和 Blob；文件名来自已授权元数据；下载链接临时挂入 DOM，触发后移除，在下一事件任务释放 Object URL，避免下载导航尚未读取时释放。成功附件以服务端 `Content-Disposition: attachment` 识别，合法 JSON MIME 文件仍按原字节下载；没有附件头的 JSON 成功状态响应按业务信封校验。非 2xx Blob 错误只由公共 HTTP 层解析，文件下载和审计导出不再次解析损坏内容；401、90002 及迟到响应遵循现有会话边界。
- 上传采用显式请求超时并保留取消能力，不增加自动重试。网络中断或取消不能被描述成服务端必然回滚；结果未知时提示刷新检查。
- 删除前确认，成功后重新读取当前分页；请求发出后若切换分类，同会话且页面仍存活时重新查询当前筛选，不把旧筛选数据回填，也不因分类代际变化跳过刷新；失败保留现有行并显示后端错误。越权、跨租户、文件不存在、大小/类型不符不伪装为成功或空列表。
- 切换筛选、账号、租户或离开页面后，旧列表和下载结果不得回写新上下文；复用现有请求代际、取消与页面生命周期模式。
- 文件限制以服务端配置为准：当前业务默认 10 MiB，而 multipart/反代允许更大的请求信封；页面不能把信封上限当成可上传文件上限，不在本任务调整这些既有容量边界。

## 非目标

不新增公开下载 URL、在线预览/编辑、分享、版本、回收站、文件所有者 ACL、配额系统、对象存储抽象或多实例共享存储。保持现有本地盘单实例与持久卷、元数据先提交后清理物理文件的规则。

## 验收入口

覆盖管理员完整文件操作、无权用户拒绝、仅 document VIEW 的普通角色可读不可上传/删除、分类裁剪、跨租户隔离、撤权后拒绝、错误 Blob 不下载及会话切换丢弃旧响应。验证使用真实 Gateway 和标准租户初始化；不通过临时补写授权或路由伪装开箱可用。

当前候选的独立环境验证见 [T-ACCESS-132](../../tasks/evidence/candidate-deployment/T-ACCESS-132/verification.md)：正常开通租户后由页面完成管理员上传、详情、UTF-8 文件名下载、分类筛选和删除；普通角色默认无文件入口，页面委派 document VIEW 后只显示可读分类且无上传/删除按钮。公开 API 补充验证未授予分类、缺少写权限与跨租户访问的拒绝；磁盘与实际下载字节一致，恢复样本保留供 T-ACCESS-134 使用。本次未改变文件契约或重新覆盖所有历史异常分支。

[T-ACCESS-134](../../tasks/evidence/candidate-deployment/T-ACCESS-134/verification.md)已验证同版本应用重启、重建及成套恢复：数据库元数据与文件卷一起备份，恢复到独立卷后实际下载字节和磁盘哈希一致，已删除样本未复活，document 分类委派及跨租户拒绝保持。结论仍限单实例本地盘持久卷，不包含跨版本迁移或多实例共享存储。
