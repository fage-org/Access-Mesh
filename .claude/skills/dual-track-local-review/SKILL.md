# 任务本地评审与收口（双轨评审，主代理直跑）

## 定位与两轨分离（2026-09-06 用户定案）

- 本 skill 覆盖**本地评审**：双轨评审（主代理直跑，不使用子代理）+ 结论处置 + 收口 checklist，是任务收口的默认动作，无需用户额外指令。
- 外部 AI 评审（claude/grok/codex）是**独立轨道，执行时机由用户决定**（见 `external-review` skill）。本 skill 任何环节不得自动串联外部评审，也不得以「还差一轮外部评审」为由阻塞收口——外部评审是否跑、跑几轮由用户拍板。

## 双轨评审执行

2026-09-26 用户定案：内部评审不再使用子代理，由主代理直跑两轨，双轨视角分离不变。两轨**先后独立执行**（按表序：先代码轨、后文档轨）：一轨排查面走完、结论分级成形后再开另一轨，两轨结论分开成文；先开轨的发现不裁剪后开轨的排查面——代码轨已报的问题，文档轨仍独立核对其规范与文档表述：

| 轨道     | 视角                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 代码轨   | 代码正确性与安全边界：并发窗口、门禁绕过、实参序、SQL、缓存失效、回归锁强度；机制重量（过度设计可裁剪项，必备要素 7） |
| 文档轨   | 规范符合性与文档一致性：project-rules 遵守、契约/schema/任务卡/AGENTS 口径一致、残留引用       |

两轨评审**必备要素**：

1. 只读纪律：禁改文件、禁 git 写操作、禁跑全量测试或容器轨。
2. 按 P0-P3 分级，每条附 `文件:行号` 与实证证据。
3. 必设「实证通过项」清单（已核对无问题的面）。
4. 必设「存疑待用户决策项」：宁可多列，每条给倾向选项与理由；上报时按 `.claude/rules/decision-question-protocol.md` 举例提问。
5. 残留搜索统一 `rg "<pattern>" -g '!docs/archive/**'`（rg 尊重 .gitignore，`target/`、`node_modules/`、`.claude/worktrees/` 自动跳过；`docs/archive/` 归档文档是唯一需手工排除的假阳性源）。
6. 适用约束：两轨针对同一基线/对象版本、任务范围、相关规范位置及有效边界。先读定案入口，按任务引用、修改与调用范围、业务概念加载相关章节；各轨可以独立扩展读取，登记历史按锚点定点读、不整本通读。候选形成后按 project-rules 文档治理核对；已修记录不豁免回归、局部接受不扩围，撤回须附匹配依据。
7. 减法检查（2026-09-20 用户定规）：新增抽象/配置项/边界分支是否有真实触发场景与调用方、既有机制（DomainService/公共工具/公共组件）能否覆盖——无真实场景或可覆盖的列为「过度设计可裁剪项」上报（位置 + 为何无真实场景 + 裁剪方向），不并入 P0-P3 缺陷分级；裁剪属设计取舍，处置时逐条交用户拍板。

## 结论处置协议

- 先按 [文档治理](../../../docs/design/project-rules.md#decision-governance)核对当前规则与有效例外；已知取舍、恢复能力、范围调整及冲突追溯原决定与替代关系。相同前提不重复决策，回归/范围外/前提变化仍核实。
- **逐条核实后再处置**，不照单全收：不成立的结论以证据反驳（先例：「测试包位置不规范」经查有域子包先例，驳回）；评审的改进建议同样核实可行性再采纳（先例：「换 effectiveOperationEntries 消除重复查询」因缺 conditionId 不可行，以技术理由登记拒绝）。
- **属实结论即类推扫描**（2026-09-20 用户定规）：核实属实的结论，在同模式调用点、同款 helper 副本、同模板页面/组件、兄弟能力包同层处排查同类问题，命中并入本轮处置清单，不留到下一轮重报。
- 属实且**修法无设计取舍**的事实性缺陷 → 直接修复，汇报中说明未中断提问的原因。**修法优先公共架构层统一解决**（2026-09-20 用户定规）：同类问题多点位时先评估上移 DomainService/公共工具/公共组件/框架层一处修复、全部调用方受益；统一方案构成大范围重构或设计取舍时退局部最小修复或交用户定夺，并说明取舍理由。
- 设计取舍/范围/口径类 → 交用户，按决策提问协议单条推进。
- 修完一轮后，新写的注释/文档/测试按同一标准自查——弱回归锁、旧行为残留注释是下一轮最常暴露的问题。

## 高频缺陷专项（评审与自审共用清单）

- **持久层单测盲区**：Mapper 调用逐个核对实参序 vs 签名（同型参换序编译通过、mock 掩盖）；XML 列名误写；涉真实 SQL 的修复配 PgIT 锁。
- **删除/退役/停用类**：被删符号与被删调用方类名在注释/Javadoc/@param 的**现在时残留**专项 grep（历史单任务 8 处）；清扫面含 mock 层、TS 响应模型、其他类同款 helper 副本、死 UI 分支。
- **门禁分支化**：无条件门禁改为枚举条件分支时必须补 else 兜底 throw（fail-closed）+ DTO @Pattern + 非法值回归锁。
- **回归锁质量**：语义修正用例须在旧实现下失败；never() 断言须经被测路径；verify 挂载用例与被证明性质同分支；同测试两段验证分段须 clearInvocations；可配置项用非默认值测边界。
- **机制重量（过度设计，2026-09-20 用户定规）**：新增机制无真实触发场景/调用方、既有机制可覆盖、为假想场景预留的边界分支或配置面——列为可裁剪项上报（裁剪参考三模式：限输入形态砍边界机制、全局强制改信任域、分阶段版本迁移合并一步），交用户拍板，不与缺陷混级。

## 收口 checklist

1. 残留检查首选 `rg` + 阳性对照（pattern 写错任何工具都静默 0 命中）。rg 无 `-r`（默认递归）、无 `--include`（排除用 `-g '!docs/archive/**'`）、二进制默认跳过；裸 `command grep` 全仓噪音比 429:112 文件（2026-09-07 实测），勿再用。超长单行字段编辑后 `rg -o | wc -l` 复核关键短语计数。`command -v rg` 不在时退回 ugrep 包装 grep（双引号假阴性旧坑同日复测已不复发）。
2. **归档连带引用扫描**：卡/计划 git mv 至 archive 后，rg 旧路径（`docs/tasks/<ID>`、`docs/plans/<name>`）核连带面同批回写——当前规则来源锚点、pending-problems 关联列、归档计划自身状态快照、看板行链接（2026-09-16 claude 外评实证：看板与批次 README 改了、registry 三处锚点与计划快照漏改悬空）。
3. 任务卡写法：禁评审日记与「用户决策」过程节；状态行不写测试总数（以 surefire 报告为准，防逐轮漂移）。
4. skill 双副本同步：`.claude/skills/` 与 `.agents/skills/` 改一份须同步全部。
5. 定案归位：本任务产生的用户决定当轮更新所属规范或任务并补来源。收口核对长期结论已归位、安排已兑现、例外仍适用和引用可解析；任务 done 不自动解除例外。
6. 提交：subject 精简一句、明细进 body；只本地 commit 不 push（用户明确要求时才 push/CI）。
